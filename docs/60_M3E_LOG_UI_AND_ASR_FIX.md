## 每会议 Log

会议目录新增 `meeting-log.jsonl`，记录 UTC 时间、事件分类、级别、事件 ID 和诊断文字；UI 按时间排列并显示本机时区。录音请求/实际状态回执、保存警告、混音/音频导出/字幕导出、本地识别结果、文字修订、归档、检查恢复与回放错误均归属于操作开始时的会议。后台 A 的成功或失败不会进入当前选择 B 的 Log。

Log 不在音频回调上执行，不提前创建录音目录；写入失败显示为 Log 问题，不改变音频任务结果。追加保留旧内容，坏行/截断尾行不阻止后续有效历史读取。并发写入、重新打开和幂等旧记录导入有合成回归；跨进程写冲突明确失败，不覆盖已有记录。单文件上限 64 MiB。

旧版会从本会议的 `meeting.json`、绑定源清单哈希的 `processing-result.json`、ASR `attempt.json`、转写版本元数据读取已有历史。采用原记录时间；缺少记录时间时采用文件修改时间。旧版从未持久保存的操作不能凭空补回；不会读取原始 stdout/stderr、提示词或转写正文充当 Log。无法读取部分旧目录时，已有 Log 仍可展示与导出。

在 **会议库 → 选会议 → Log → 导出 Log** 保存独立 UTF-8 TXT。选新文件名，不覆盖原件或旧导出。分享版不附音频、字幕、模型输出、配置；会去除本机路径、用户名、URL、已知题名及明确的提示词/正文标签。旧自由文本仅本机显示，导出采用结构化状态/耗时及已识别诊断摘要。题名元数据损坏时进一步省略详情，仍导出时间/分类/级别/错误码并说明隐私降级。导出完成不代表上传。

## 识别失败与修复范围

用户报告：端点兼容、mic 关闭、32.831 秒音频混音和回听成功，随包 base 识别耗时 42.8 秒后报“转写起止时间倒置、越界或质量标记无效”。没有取得该机原始识别时间戳，**未证明该样本完全同因，也没有宣称目标机修复后通过**。

既有中文 SAPI 合成样本在本机真实 CPU/base 重跑，再次产生 `39840 ms > 39715 ms`。旧实现严格拒绝整稿；新版仅对 **本地 Whisper 最后一段、起点在音频内、尾端超出不超过 250 ms** 的近似时间修正到完整音频边界。保留全部文字、原始 SRT/JSON、旧版本，并在 revision、attempt、结果提示和 Log 中记录原值、新值与修正幅度。人工导入不采用这项宽限。倒置、零长、整段越界、非末段越界和更大偏差继续拒绝，并给出具体段号、时间及超出量。没有修改原音频、混音算法或 Complete 状态。

真实 SAPI 中/英/混合三样本均完成管线，58.285 / 51.672 / 79.634 秒。中文尾端修正 125 ms；14 项输入/引擎/模型哈希不变。准确率仍需人工核对，这不是金融语料、自然中文会议或长会质量验收。
