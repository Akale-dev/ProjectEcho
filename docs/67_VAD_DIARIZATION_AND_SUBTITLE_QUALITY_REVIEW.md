## 1. 四种能力分别解决什么

| 能力 | 回答的问题 | 对用户的效果 |
|---|---|---|
| VAD：语音活动检测 | 这一段有没有人在说话？ | 识别语音区间和停顿，给会后识别与切分提供辅助依据 |
| ASR：语音识别 | 说了什么？ | 得到文字、模型标点及初步时间 |
| 对齐 | 这些字词分别在什么时候说出？ | 改进字幕起止和点击回听定位 |
| 说话人分段/聚类 | 哪些时段属于同一个匿名说话人？ | 按 A、B、C 分段，减少把两个人的话接成一句 |

“把同时讲话的两个人拆成两份干净音频”还属于另一类音源分离任务。说话人分段并不自动完成这件事，也不自动知道真实姓名。

## 2. whisper.cpp 的 VAD 与当前接入情况

whisper.cpp 的 VAD 会先检测语音，再将检测到的语音区间交给识别器。官方提供 Silero VAD 接入，需要另有 VAD 模型；可调检测阈值、最短语音、最短静音、边缘保留等参数。[官方 VAD 说明](https://github.com/ggml-org/whisper.cpp/blob/927cfce34f31707e17f2bff35c349632fb9e2c3a/README.md#voice-activity-detection-vad)

预期收益是减少无声时段的无效识别，并给切分提供停顿依据。它不能决定语法句末，也不区分说话人；低声、很短的“对/不/yes/no”和背景人声必须纳入测试，不能把没有检测到语音直接等同于没有发言。

本次实际查看随包引擎帮助，确认它提供 `--vad` 和 `--vad-model`。帮助列出的默认值包括阈值 0.50、最短语音 250ms、最短静音 100ms、语音边缘保留 30ms。这些是引擎默认值，不是已经验证适合本项目会议的参数，更不应直接用 100ms 停顿生成一条字幕。

当前 ProjectEcho 调用没有传入 VAD 参数，随包目录的文件名检查也未发现 Silero/VAD 模型。现有“全数字零输入不调用模型”的保护只是特殊静音检查，不是 VAD。

建议只在会后识别副本上使用 VAD。完整原音频、回放时间轴和暂停时长继续保留。若识别过程临时提取或拼接语音，必须验证段落和 token 时间正确映射回原文件；不能让原来第 20 分钟的话变成压缩语音流里的第 8 分钟。应保留 VAD 区间和映射，分别校验字幕与 token，而不是只补一个总偏移。

## 3. whisper.cpp 对“说话人分离”的支持边界

随包帮助确实列出 `--diarize` 和 `--tinydiarize`，但二者不能等同于普通会议中的完整多人识别。

| 功能 | 实际含义 | 本项目适用性 |
|---|---|---|
| `--diarize` | CLI 按立体声两路的能量比较给出声道标签 | 需要输入本身有有意义的左右分路；普通多人单声道会议不因此变成逐人标签 |
| `--tinydiarize` | 需要专用 tdrz 模型的实验性换人检测；官方示例使用 small.en-tdrz | 可标记换人，不能直接承诺中文多人稳定 A/B/C 聚类或实名识别 |
| 独立说话人分段管线 | 用分段模型、声音特征和聚类生成匿名标签 | 才是需要评估的完整路线；当前 ProjectEcho 未实现 |

依据：[CLI 声道判别实现](https://github.com/ggml-org/whisper.cpp/blob/927cfce34f31707e17f2bff35c349632fb9e2c3a/examples/cli/cli.cpp)、[tinydiarize 说明](https://github.com/ggml-org/whisper.cpp/blob/927cfce34f31707e17f2bff35c349632fb9e2c3a/README.md#speaker-segmentation-via-tinydiarize-experimental)。

当前识别输入是完整混音的 16kHz 单声道副本；程序未请求以上两种功能，也没有把说话人输出接入字幕。保留独立 remote/mic 原轨有助于区分来源，但 remote 内仍可能有多人，mic 也可能收到多人或回声。来源不能自动等于某个人。

我倾向验证 **sherpa-onnx 的离线说话人分段**：它已有原生接口及 C# 示例，示例组合包含分段模型、说话人特征模型和聚类，符合本项目优先研究 Windows 本地集成的方向。[官方 C# 示例](https://github.com/k2-fsa/sherpa-onnx/blob/master/dotnet-examples/offline-speaker-diarization/Program.cs)

这只是候选，不是已通过的方案。需单独核对模型许可、分发条件、中文/中英混合、短插话、人数未知和重叠发言表现；也不能继承 Whisper 的 Vulkan 验收。首版可先测 CPU，输出仅为本场 A/B/C 或“不确定”，由用户自行命名。同名 Speaker A 不跨会议自动合并。

## 4. 现有断句逻辑为什么可能出现这些问题

实现见 [WhisperSentenceSegmenter](../src/ProjectEcho.Core/Transcription/WhisperSentenceSegmenter.cs)。

| 代码事实 | 可能的表现 |
|---|---|
| 主要在句号、问号、感叹号处寻找拆分点 | 口语标点少、逗号串句时，一条字幕仍然很长 |
| 必须有与文字边界严格对应的可用 token 时间 | 某个 token 缺时间、重叠、回退，或句末落在 token 内部时，可能保留整个原段 |
| 合并条件允许相邻未完句间隔不超过 1 秒、合并后不超过 30 秒且少于 240 字符 | 短停顿甚至换人可能被合并；30 秒/240 字只是合并上限，并不会主动拆短原来的长段 |
| 只有相同 SpeakerLabel 才合并，但当前通常都没有标签 | 两个未知说话人都为 null，不能靠这项条件阻止跨人合并 |
| 起止时间沿用模型原段和 token offsets | 分句文字更合理，也可能仍提前或滞后 |

当前没有请求 DTW，对齐信息中的 `t_dtw` 也没有进入分句算法；`-ojf` 的完整 token 输出不等于已经做了专门对齐。现有百分秒显示只改变显示精度。末句最多 250ms 的越界修复也只处理文件尾边界，不能校正整场字幕。

人工修订当前只允许改文字，段标识、时间和说话人保持原样。因此要在程序里提供时间微调或拆分/合并，也需要扩展版本合同，不能直接改写旧稿。

## 5. 针对三类问题的建议路线

### A. 可读性：独立的字幕重新分段

把字幕展示段与语法完整句区别处理：先尊重可信换人点和明显停顿，再结合句末标点、分句标点、阅读长度及持续时间选择边界。原来几十秒的一句话，可以显示为几段连续字幕，文字顺序和全文不变。

可先把单条约 4–8 秒、中文约 20–40 字作为实验偏好，而不是硬标准。达到长度时在附近可信字词边界切开；没有可靠时间边界时保留警告，不按字数比例编造时间。不能为了凑长度跨明显停顿或合并不同说话人。

已有 token 数据足够时，可新增“重新分段”生成独立版本，避免每次重跑整场识别。旧原稿、人工修订和原音频继续保留；缺少所需数据时明确提示需重新识别或对齐。

### B. 时间：增加音频对齐，再生成字幕边界

第一步验证当前引擎的 DTW token 时间路线；官方头文件仍将它标为实验能力。[固定引擎版本的接口定义](https://github.com/ggml-org/whisper.cpp/blob/927cfce34f31707e17f2bff35c349632fb9e2c3a/include/whisper.h)

不能只加一个命令参数：还要解析实际输出、确认时间单位与语义、处理无效对齐和标点、检查所用模型/后端是否真正启用，并验证与 VAD 原时间映射的组合。先用 CPU 对照，再验证目标 Vulkan 路径，不承诺开关一开就更准。

若 DTW 仍达不到要求，再评估独立的音频—文字强制对齐模型。WhisperX 是可做对照的现成路线，采用语言相关对齐模型，并提供说话人管线；它增加 Python 等依赖，官方也列出数字/符号、重叠发言和说话人识别的限制。[WhisperX 官方项目](https://github.com/m-bain/whisperX)

强制对齐不能修复所有识别错字；漏掉的短词或错误文字也可能导致对齐失败。结果仍需保留质量标记，不能把算法输出直接改为“已验证精确”。

### C. 换人：说话人分段参与字幕生成

取得匿名说话人时间区间后，将其与已对齐的字词交叉匹配。可信换人点优先成为字幕边界；在同一语法句中换人，也应分别展示。

重叠发言、短插话和低置信区间不强行归给一个人。可保留“不确定/可能重叠”的提示，不能为了生成漂亮的单行字幕删除另一段文字。听起来相似的声音及同人的音色变化都需测试。

建议同时提供用户拆分/合并字幕、微调起止、修改匿名说话人标签的入口；所有操作保存为新修订，并保留修改依据。可提供回听提前少量时间的选项帮助听清句首，但它不能冒充时间轴精度修复。

### D. 整体组合

建议链路为：完整音频副本 → 语音区间检测 → Whisper 转写 → 音频与字词对齐；另一路从音频做说话人分段，最后共同生成可读字幕并供人工校订。

M4 的文本模型可以辅助标点或提出语义断句建议，但不能从文字恢复真实声音时间或辨认说话人的音色；不能让它重写句子后直接沿用旧时间。以上工作应归入 M3 会后字幕质量改进。

## 6. 实施顺序与验证

建议先做现有长段/合并规则调整、独立重新分段和 VAD/对齐小样；随后接入说话人分段；最后补人工时间/标签修订和完整回归。三个问题的最终验收分别进行，不能只凭字幕看起来短了就说时间或换人已修复。

优先样本包括：连续长句、短停顿、长静音后首句、轻声“对/不”、快速轮流发言、中英切换、人名/金额/百分比/日期，以及重叠讲话。使用合成或明确授权的非敏感材料，人工标注部分原话与时间作对照。

记录关键短词漏识别、分句可读性、起止边界误差、说话人错分/漏分、处理耗时、内存和取消行为。VAD 开关、普通时间与 DTW/独立对齐分别对照，并检查末尾、长静音和所有转换后的全局时间不变。
