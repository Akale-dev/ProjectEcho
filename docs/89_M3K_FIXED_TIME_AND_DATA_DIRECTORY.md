## 时长与两次错误的关系

所提供同一会议的清单、混音及ASR输入时长一致，没有发现会议被算短：

| 来源 | 核查结果 |
|---|---:|
| 会议清单 `duration100ns` | 24753251406，即41:15.3251406 |
| 混音118815607帧 / 48000Hz | 41:15.325145833 |
| ASR输入39605202帧 / 16000Hz | 41:15.325125 |
| 字幕/attempt的整数毫秒上限 | 2475326ms，即41:15.326（向上取整） |

混音与ASR输入仅差0.020833ms；文件头、真实EOF、输入/混音/清单/索引哈希绑定通过。截图播放器41:15.32为百分秒显示，不是底层上限精度。

实际加载已交付M3K Core，对旧恢复稿末条无时间字幕作纯内存编辑，复现截图：`41:09:01`在`时:分:秒`格式中为**41小时9分1秒**，`41:11:00`为41小时11分，当然超过41分钟。改成`00:41:09.010`、`00:41:11.000`，同一条字幕立即合法。没有保存或改写原稿。

旧识别失败的末条模型时间为41:10.160–41:16.240，结束比真实音频超914.875ms；末词token结束也超864.875ms。当时整稿拒绝与此真实模型估计越界有关。之前M3J已将无法证明时间的该条保为“无时间”，文字仍完整。**当前输入格式歧义与原模型末端越界不是同一原因**，没有放宽时长或把全部字幕整体平移。

限度：项目内未找到截图版本前缀`4310b4ac`的revision.json，不能声称已读取截图这个版本的全部字段；核查依据是提供的原会议、旧attempt、正式恢复版本和真实音频。remote原轨没有提供，不把这次WAV/metadata核查冒充原始采集全链验收。

## 输入框改动

- 保持原来的160DIP左侧编辑列，时间控件118DIP；没有挤占原字幕文本框。
- 单个边框内固定`时 : 分 : 秒 . 毫秒`四个数字栏，两个冒号和小数点不属于可编辑文字；数字栏拒绝非数字/整段时码粘贴，空格键也明确拦截。
- 毫秒栏按整数毫秒输入：1=001ms；失焦仅对非空数字左补零，不把空栏擅自补为0。
- 对原本无时间的段，首次输入某格时其余格初始化为零；编辑已有值后清空单格保留未完成草稿，只有整行×/Ctrl+Delete才清空该条时间。起止同时空才表示无时间。
- 明示格式、本字幕版本时长、已校验音频时长和当前输入的小时/分钟/秒解释。开始越界、结束越界、反序分别提示；没有改变原会议时长、ASR时码策略或逐段保全文逻辑。
- 编辑器桥接API可读取旧完整时码与明确的两段分钟时码；界面数字栏不接受含分隔符的粘贴，不按会议长度猜测三段时码含义。

## 数据目录与录音状态

旧版没有保存所选数据目录，重启构造器总是回到程序旁Data。补丁保存最后显式选择，后续启动恢复；不可用时保留原路径并提醒，不静默切回默认或创建替代目录。路径存应用自身配置，不使用系统注册表或全局用户配置。

旧版未留历史选择，因此首次更新需要选一次原数据目录。以后同一便携目录重启继续使用；升级时应保留应用自身设置和原数据，不能把新解压目录当作已拥有旧版未保存的选择。

录音状态卡上下内边距从10改25DIP，内容/电平不缩放，普通卡预期约120→150DIP。声音来源区域不动；长处理结果在较矮窗口可能需少量滚动，不保证任何缩放下都首屏容纳全部内容。
