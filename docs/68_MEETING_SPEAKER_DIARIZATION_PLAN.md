# 68｜同场说话人分段与 A/B/C 字幕标记规划

实施更新（2026-10-04）：用户已明确启动M5；实现、真实测试、质量失败和未测见[75](75_M5_MEETING_SPEAKERS.md)、[78](78_M5_NATIVE_EVIDENCE.md)、STATUS及验收表。下方“仅规划”是当时快照，不代表当前未实现，也不把M5的PARTIAL闸门升级为PASS。

初稿日期：2026-10-03；2026-10-04 按用户确认的三阶段路线更新。实施基线：M3Hfix 完成后的实际交付。所属阶段：**新 M5**，在 M4 中文 ASR 与句子定位后推进。状态：仅规划，未启动开发、安装、模型下载或音频测试。总计划与增量闸门见[70](70_M4_M6_LOCAL_ASR_ROADMAP.md)。

当前范围：自动识别换人、在字幕中标记说话人 A/B/C，并把同一场会议中再次出现的同一个人匹配到原代号；**用户修改显示名称为必交付**。复用 M4 满足句子定位的必要音文对齐，M5 只补可靠换人所需的局部映射，不做逐字显示/编辑或通用字幕美化。本文件延续[67号评审](67_VAD_DIARIZATION_AND_SUBTITLE_QUALITY_REVIEW.md)，冲突处以70号最新范围为准。

## 1. 功能目标与交付效果

目标是会后、离线的说话人分段和聚类。先分析一场会议里的声音，将属于同一说话人的时段归为一组，再把结果应用到用户选择的字幕版本。普通单声道混音也可以作为这种算法的输入，不要求录音本身已经一人一轨。

预期展示示例（人为构造，不是测试结果）：

| 时间 | 显示 | 行为 |
|---|---|---|
| 00:10 | 说话人 A：先看收入。 | 首位可可靠归组的说话人 |
| 00:18 | 说话人 B：同比增加多少？ | 新的说话人 |
| 00:24 | 说话人 A：大约百分之十。 | A 再次发言，继续使用 A |
| 00:32 | 说话人 C：这里需要核对口径。 | 第三位说话人 |
| 00:41 | 说话人 B：我来核对。 | B 返回，继续使用 B |

“换人时拆段”与“同人返回匹配原代号”同时列为核心要求。只发现某处声音变了、每次递增编号，不能算本功能完成。

首版范围限定在同一场会议。不同会议各自的 A 没有身份对应关系；不建立跨会议身份库，不识别真实姓名，不分析人物属性，也不承诺把重叠讲话拆成独立干净音轨。原 remote/mic 只代表音源，不能自动命名成“对方/我”或某个人。

## 2. 推荐的本地引擎路线

建议优先验证 **sherpa-onnx 的离线说话人管线**，以原生运行库/C# 接入。候选组合是 pyannote segmentation 3.0 的 ONNX 分段模型，加 3D-Speaker ERes2Net 的声音特征模型，再进行全场聚类。官方资料提供这一路线、C# 示例，以及已知人数和未知人数的配置方式。[官方模型与管线说明](https://k2-fsa.github.io/sherpa/onnx/speaker-diarization/models.html)、[官方 C# 示例](https://github.com/k2-fsa/sherpa-onnx/blob/master/dotnet-examples/offline-speaker-diarization/Program.cs)

以上只是首个验证候选，未锁定版本或分发模型。开发启动后，需先核对实际二进制、模型来源/许可/哈希，并在目标 Windows 上测试中文、中英混合、电话音质和多人轮流发言。上游样例的速度和正确标签不作为 ProjectEcho 的验收证据。

初版先建立 CPU 基线，实际需要时再研究加速；不继承 Whisper 的 Vulkan 通过结论。正常使用目标为无需额外 Python/Node、无需云端账号或自动下载。它负责声音归组，Whisper 或 M4 接入后的 Qwen 负责文字；不额外部署通用文本 LLM，也不用文字猜声音身份。

默认人数设为“自动”；可提供可选的已知人数提示帮助重新分析。不能照搬官方四人样例的固定人数，也不能从转写中的人名数量推测人数。聚类阈值由样本验证确定，不把相似度直接显示成“身份正确率 99%”。

不因 M5 强制改造现有 Whisper VAD。说话人管线本身的分段能力按实际需要评估，可复用 M4 的窗口与映射，但不能把其 VAD 未命中区间永久删除后才分析说话人；轻声和短插话必须可检验。不重复堆叠一套不必要的 VAD，不改变采集或既定录音时间轴。

## 3. 如何让 A 再次出现时仍然是 A

建议以完整会议为一次分析范围，流程为：

1. 从已校验的完整音频准备会后副本，遵守该文件的 timelinePolicy：新录音去暂停、旧录音保留 elapsed 时间；真实静音和缺口仍保留，不重复删减或补回暂停。
2. 检测局部发言区间和可能的换人位置。
3. 从有效语音片段提取声音特征，短到不足以判断或明显受干扰的片段保留不确定状态。
4. 综合整场资料聚类，使不相邻但属于同一人的片段落在同一组；分窗处理时也必须做全场匹配。
5. 按各组首次可靠出现的顺序映射到 A、B、C，保存稳定的内部 speakerId 与显示代号。
6. 完成后一次性发布带说话人的字幕版本；处理中不把临时编号当作最终身份。

不能只把当前一段与上一段比较，也不能把长录音各片独立编号后直接拼在一起。A 在十几分钟后返回，仍需与本场 A 的有效声音特征比较。短暂插话不应轻易变成新人物，但也不能因为太短就把对应文字删除或直接归给前一人。

保存后的版本在切页、重开和索引重建后保持同一套代号。重新运行模型生成新分析版本；若新版本的聚类确实变化，应明示差异，保留原版本和用户修正。首版不承诺不同模型/不同运行得到完全相同的聚类，不能静默把用户确认的 A 改成 B。

## 4. 复用句子定位，补充换人处的必要映射

这是本次规划最重要的技术边界：知道 12.4 秒换人，并不自动知道现有一句长字幕里第几个字是在 12.4 秒说出的。

M5 仅处理换人所需的边界，不调整整场字幕节奏或通用长度。优先复用所选版本的句子时间，以及经过验证、与该版本文字严格匹配的音文映射：Whisper token 或 M4 的对齐结果均可，不能把 Whisper 时码直接套到不同的 Qwen 文字上。句子回听不要求逐字界面；句内换人仍需局部文字边界证据。

| 字幕情况 | 建议行为 |
|---|---|
| 一整条字幕明确属于 A | 添加 A，原文字和起止时间保持不变 |
| 换人位于两条字幕之间 | 各条分别标 A、B，并阻止后续跨说话人合并 |
| 一条字幕内部发生可靠换人，且有可信字词边界 | 在该边界拆为 A、B 两条，完整保留文字及原段引用 |
| 一条字幕跨多人，但没有可靠字词时间 | 标为“多个说话人/需确认”，显示候选换人时刻，供用户选定文字切点；不按字数均分时间 |
| 短句或声音证据不足 | 保留文字，显示“说话人待确认”，不强塞进 A/B/C |
| 可能存在重叠 | 只有模型提供相应证据才标注重叠；否则显示归属不确定，不捏造两个人的独立文字 |

说话人边界与 token 边界可能都有误差。匹配需要有受控容差，必要时拒绝自动拆分；每个输入字符只归属一次，不能丢词、重复填词或把否定词划到另一人。新边界仍标为估计，不因显示到百分秒就标为准确。

有原始 token 输出时，应验证它确实属于所选音频和转写原稿；不能随便挑同一目录的最新 JSON。当前人工修订可能已经改过字词，需把修订与原稿对应起来。修改处没有可靠映射时保留待确认，不用旧原文覆盖用户校订。

导入的 SRT/VTT 通常只有句级时间：单一说话人的整句可以标记，句内换人可能需要人工切点。只有无时间 TXT/MD 时，不自动生成定时说话人字幕；可以查看独立的音频说话人区间，但文字归属需另有时间依据。本轮不为此自动重跑 ASR 或强制对齐。

## 5. 界面、自动标记和必要的人工纠正

建议在“转写与字幕”里，为选定版本增加 **“按说话人分段”**。第一次需配置好本地模型；点击后才启动会后处理。完成时生成独立的“带说话人”版本并可切换查看。已有录音无需重新录制；音频与定时字幕就绪时，也应支持只运行这一步。

未来可增加“识别完成后自动分析说话人”的可选项，默认关闭、由用户主动开启。首个版本先把独立按钮流程做好，避免把每次普通识别都变成额外模型任务。

字幕行显示代号、时间和文字；颜色仅作辅助，不能只有颜色没有文字标签。换人的边界必须保留，即便两人合起来语法上恰好是一句话。同一个人的原有多条字幕可继续保留，不能为了同代号把一整场都合成长段。

建议首版纳入以下纠正动作，确保自动误判后可用：

- **改这段的说话人**：把选中字幕从 A 改为 B，或设为待确认。
- **合并人物代号**：用户确认 A 和 C 实为同一人后，合并本场相应映射；不改字幕文字。
- **拆出另一位说话人**：把选定的错误归组片段移到新代号，避免只能把全场 A 一起改名。
- **人工确认句内切点**：对已标记的换人位置选择文字分界；这是换人所需的局部操作，不扩成通用时间编辑器。

这些动作保存为新修订，保留父版本。显示名称默认用 A/B/C；**用户自行改名属于首版必交付**，并保持内部 speakerId 不变，不建立联系人系统。人工修正不作为训练数据自动上传，也不让下一次自动任务覆盖它。

## 6. 保存与导出需要一起完成

目前 `TranscriptSegment` 已有 SpeakerLabel，但它只是字符串，尚不足以保存自动聚类和修正历史。当前修订接口只允许改文字；常规字幕行及 SRT/VTT/TXT 导出也没有完整使用这个字段。只在界面前面加“说话人 A”不能完成整项需求。

建议增加两层版本化结果：

| 层 | 保存内容 | 用途 |
|---|---|---|
| 音频说话人分析 | 音频指纹、引擎/模型/参数、分析范围、时间区间、speakerId、代号与质量状态 | 同一完整音频可以复用已保存分析；失败和重跑有记录 |
| 带说话人的字幕版本 | 输入转写版本/指纹、所用说话人分析版本、原段及文字范围、新段与 speakerId、人工修正记录 | 明确每条新字幕来自哪里，保持旧稿和人工编辑 |

内部稳定 ID 与显示代号分开，改标签不改身份引用。数据继续保存在本地权威文件中，SQLite 只作可重建索引。新合同要兼容旧 v2，不给旧会议凭空补人名、时间或说话人字段。

第一版没有跨会议匹配需求，因此声音特征优先只在本次分析内使用；若实测必须保存中间特征缓存，应放在对应会议的数据目录、明确随会管理，不建设独立全局声音身份库。

导出增加“包含说话人标签”选项，使用当前显示名称或默认代号。启用时，SRT/VTT 可用可读文字前缀 `[说话人 A]`，TXT 可按相同标签展示；关闭时保持现有纯文字输出。前缀应在导出时生成，不写进原始发言文字，避免重复加标签、污染搜索或被 M6 复核及未来 M7 分析当作口述内容。

SRT/VTT 中的可读前缀不等同于可无损还原的结构化身份；再次导入不能默认把任意 `[A]` 文字当作可信说话人。稳定身份与版本关系保存在项目数据中，若以后提供结构化导出，再显式携带这些信息。

## 7. 资源、任务和范围控制

建议用一个专用的会后处理进程隔离原生模型运行，提供可取消任务；不放入 CaptureHost、不访问麦克风、不进入录音回调，也不建设通用插件/调度平台。

先以一次一个重型后处理任务安排，采集优先。开始下一场会议不应等待说话人分析完成；资源竞争需要退让、延后或取消当前处理，已有音频和字幕继续保留。切换会议后，后台结果仍归属启动时的会议与版本。

现有数据根和可恢复删除规则继续适用。任务进行时保护依赖资料；取消/崩溃的中间结果不发布成完成版本，重试另存新尝试。日志只记录必要诊断，模型输入、完整字幕和声音特征不进入可分享诊断。

主要场景仍按约三小时会议规划，但当前没有这条新链路的性能证据。全场聚类不意味着必须在 WPF 中复制整场音频；需核对引擎的实际内存接口和峰值。如果分窗处理，必须保存全场一致的分组关系，不能用分片各自 A/B/C 的方式换取低内存。

本次暂缓：通用可读性重分段、逐字界面与通用时间编辑器、Whisper VAD 参数界面、实时字幕、跨会议人物匹配、音源分离、多源身份推断、M7 自动纪要。M4 所需句子音文对齐不在此暂缓范围；M5 仅对可靠换人点进行必要字幕拆分。

## 8. 后续真正启动时的实施顺序

| 阶段 | 内容 | 完成条件 |
|---|---|---|
| 先验证声音归组 | 核对许可与 Windows 原生运行；自动人数；同人多次返回 | 标注样本能检验换人及 A-B-A-C-A；记录错误和资源，不拿演示文本替代模型实测 |
| 再接入字幕 | 精确绑定音频/转写；句间标记；句内可靠拆分与不确定回退 | 全文无丢失、无重复，原时间轴和旧稿保留；不跨说话人误合并 |
| 补纠正与交付 | 单段改人、人物合并/拆出、带标签导出、版本重开、取消与长会 | Windows 实际界面/导出/故障隔离通过，三小时资源和质量有独立证据 |

最小交付应同时有自动换人、同场一致代号、显示改名、必要纠错、版本保存和标签导出。只有把一句字幕加上 A 或 B，不应当作完成。M5A/B/C及P5-01–04的统一闸门见70号主计划，全部保持NOT_RUN直到实际执行。

重点验收情形：

1. A-B-A-C-A-B，间隔较长后返回也正确匹配；保存重开代号一致。
2. 不同但音色相似的人不随意合并，同人音量或语气变化不轻易拆成多人。
3. 人数未知时自动估计；已知人数提示作为独立配置验证。
4. 中文、英文和中英切换；同人换语言不因此换代号。
5. 很短的答复、轻声、电话压缩、背景噪声、回声和重叠发言；不确定时保留文字与提示。
6. 换人在字幕间/字幕内部/一个字词附近；缺 token、错 token、人工改字、导入 SRT 均有正确处理。
7. 人工纠正、取消、重试、切会、重开、旧数据读取、索引重建及导出标签开关。
8. 后处理不影响下一场录音；整场音频/原稿哈希不变，尾句不丢；目标长会内存与耗时可接受。

声音归组评估应允许 A/B 字母整体置换后比较真实分组，避免仅因模型原始编号不同就判错。实际产品显示则按首次出现规则固定。质量报告同时统计说话人混淆、同人被拆、不同人误合、待确认覆盖率和字幕错归率；不能只给一项总准确率，也不能靠把所有段都标未知来通过。

数字质量门槛在建立标注样本后、发布判断前明确固定；此时不凭没有运行过的模型承诺准确率或三小时处理速度。
