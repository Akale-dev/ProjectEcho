# ProjectEcho 便携版使用说明（M2 + M3）

本包是 Windows x64 便携验证版，包含 M2 录音导出与 M3 文字工作流。完整包含主程序、CaptureHost、.NET 10.0.12 运行时、NAudio 3.1.0 和许可清单；正常录音、导出和文字导入不需要安装 SDK、.NET、Node、Python、FFmpeg 或模型。未加入 SQLite。尚未在无预装 SDK/.NET 的干净 Windows 上完成录音、回放、压缩导出验收，不能据此称为生产版。

## 按任务使用

左侧分为录音、会议库、导出音频、转写与搜索、诊断与设置。顶部常驻本场来源范围和独立麦克风状态，底部常驻录音操作；切换页面不会开启音频采集。可在侧栏切换明暗主题。新图标是青绿底的白色声波与暖色回声弧。

- **录音**：选来源、确认范围与可选 mic，预检后主动开始。按停止后等待原件保存。
- **会议库**：点击读取列表，选中历史会议后生成混音、回听或修改标题/项目。检查和恢复入口在本页。
- **导出音频**：选择 M4A、MP3 或 WAV；高级选项设实际字节、时长和重叠。所有导出都只写本地文件。
- **转写与搜索**：分为导入文字、搜索与校订、本地识别。没有模型也能使用前两项。
- **诊断与设置**：查看保存状态、预检详情和数据目录。完整验收限制保留在本页。

## M3：导入、校订和本地识别

先在会议库选择已保存的普通录音。在转写页选择 TXT/MD/SRT/VTT/ProjectEcho JSON 文件并填写来源，点击导入。TXT/MD 保持无时间文字；字幕与 JSON 时间为近似值，越界或倒置会明确拒绝，不根据文字长度猜时间。文件上限为 8 MiB，原稿单独保留。

如果转写对应某个导出分片，展开时间映射，选择该次 `export-manifest.json` 或混音目录 `export-records` 中的本地记录，填写 `part-0001.mp3` 等精确文件名。先生成本场完整混音以核对哈希，不能拿另一场的映射套用。本版不猜测外部服务是否去除了编码延迟；落在未映射填充区间的字幕需要先核对时间来源。

搜索和校订页可以读取各原稿/修订，按关键词搜索本场或当前数据目录的会议。搜索不使用 SQLite、不执行文字中的脚本/指令。选一段修改文字后保存为新修订；原稿、父版本、时间和说话人字段保持不变。重叠段落不会自动删除。定位回听要求该场已生成完整混音；录音及暂停期间所有回听仍禁用。

本地识别是可选的 whisper.cpp CLI 适配器。自行准备可信的 `whisper-cli.exe` 和兼容模型，在界面选路径、核对模型许可（可填写可信 SHA-256）后保存本机配置。应用不会下载模型或发送音频。点击识别后先生成完整 16 kHz mono PCM16 副本，再以独立 CPU 进程运行；可取消或重试，每次输出与耗时单独保存。关闭窗口会等任务收尾，旧文字任务不会禁止开始下一场录音。全数字零 PCM 不调用模型、不生成文字；其他安静片段仍需人工核对幻觉。

当前未安装/下载 whisper.cpp 或模型，真实中英混合识别、速度和准确率为 **NOT_RUN**；进程夹具测试只验证适配和失败/取消行为。具体实现与验收证据见开发仓库 STATUS。

## 开始使用

1. 保持整个文件夹结构，放在普通用户可写的位置。双击 `ProjectEcho.exe`；不要只复制 exe，也不要以管理员身份运行。
2. 默认数据位于文件夹旁的 `Data`，可在界面选择其他可写目录。数据目录包含录音原轨、索引、恢复信息与派生混音，请自行保管。
3. 每场先核对实际音频进程树/来源范围；mic 默认关闭，只有明确启用后才采集。Zoom/Webex 的静音与录音器 mic 开关不同。
4. 网页会议使用专用 Chrome 实例，单独 user-data-dir；普通窗口、无痕窗口不能证明音频隔离。来源边界是整个进程树，不是标签页或某个参会人。
5. 主动点击开始；暂停保留完整时间轴并真正停采。停止后等保存完成，才能回放。程序不会自动入会、录音或上传。
6. 保存后后台生成完整混音 WAV 和可用时的 M4A；编码失败保留 WAV 和原轨，可重试。导出选择格式、实际字节上限、时长和重叠；导出文件夹只包含明确生成的混音/分段与相应清单。
7. 如需外部转写，核对接收方要求后自己上传导出文件。导出不等于上传；程序没有自动上传、API 密钥或模型要求。

## 音频格式和时间

WAV 为 mono PCM16 真混音，保留暂停和单轨缺口。M4A 和 MP3 使用 Windows 自带 Media Foundation 编解码器，不随包重分发系统 codec，也不在运行时下载。

MP3 为 48 kHz / 96 kbps 单声道。每次编码先以本地合成 PCM 检查当前编解码器的延迟，再逐 MPEG 帧扫描并解码到 EOF，核对时长、真峰值及实际字节。去除 Windows 自动生成的有问题的补齐标签，清单显式记录已验证的 673 帧开头延迟和尾补齐；其他解码器时间仍仅为近似。每个分片预留 8192 帧开销并按实际结果检查限制；这不会裁掉原始尾声。目标机校准不符时明确失败，WAV 保留。两小时 MP3 与跨播放器兼容性尚未实测。

普通大小的 WAV 使用 RIFF 容器，应用优先回放它。超过 RIFF 容量的完整混音使用 64 位长度的 RF64，仍保留完整 WAV；当前内置 WPF 播放器不直接打开 RF64，而选用已完成编码与校验的完整 M4A 回听副本。若该副本尚未成功生成，应先重试合并/编码或导出兼容大小的 WAV 分片，不把无法直接回放 RF64 解释为原轨丢失。跨 4 GiB 读取/分片已有合成稀疏文件证据，不能把它当作超大 RF64 全文件实际回放或压缩已通过。

完整 WAV 和每个新分片都经过真正的重建峰值检测，不能把样本最大值当作真峰值。检测采用 ITU-R BS.1770-5 的四倍过采样 FIR；默认派生文件处理到 -2 dBTP，给要求的 -1 dBTP 上限留出测量与量化余量。需要衰减时，对整个派生文件施加固定比例，时间轴与源轨保持不变；不会把静音放大。M4A 完成后用浮点 PCM 解码，再次检查重建峰值；若编码引入过冲，从未改动的 WAV 最多重编码四次，否则明确失败。清单记录实测峰值、固定衰减和尝试次数。

默认 M4A 为 48 kHz / 96 kbps。编码完成后逐帧解码至文件末尾，核对实际格式、帧数和字节数。为保障极短分片及尾声完整，AAC 输入补 2048 帧静音，另有最多 1023 帧编码块补齐；清单单独记录源内容长度及尾部 padding。48 kHz 时附加尾部少于 64 ms。原会话内容不会因 padding 变长，也不会丢掉末尾。

导出预算包含这些补齐及容器开销：M4A 先在用户最大时长中预留 3072 帧（48 kHz 时 64 ms），按码率估计时另留 5% 字节余量，再以实际文件字节数和实际解码时长检查。超限会缩短内容并有限重试，最后一片仍覆盖全部尾段；大小/时长太小或无法容纳重叠时明确拒绝。默认 20,000,000 字节仅为保守本地预算，不代表任何上传服务允许的上限。

本机 Windows Media Foundation 解码的首尾标记验证无首端偏移；其他播放器或转写服务对编码 priming 的处理未统一验证，外部转写时间戳应视为近似。M0 已知 QPC-only 时钟限制和尚未完成的两小时双轨同步验收仍有效。

每个 M4A 在发布前另检查容器时间表与实际完整解码帧数一致。本机旧式 Windows 播放组件可能只把 M4A 时长属性显示到整数秒；程序不使用该属性裁剪或结束导出，应以验证清单的内容帧数/时长为准。属性精度限制不表示文件已被截短，回放完整性仍须核对实际首尾内容。

当前普通 RIFF 与 M4A 的实际 WPF 输出首尾标记已有通过记录（docs/44），M4A 的容器/完整解码也已通过。WMP 属性精度限制保留为已知问题，不能把整数显示值称为准确时长，也不能据此自动截取音频。

## 平台与验收边界

当前开发机为 Windows 11 25H2，build 26200.9457，x64。本轮105组默认自动测试通过（含MP3实际文件编解码、M3导入和合成CLI进程夹具）；真实设备采集未在本轮重复。既有7201.166秒远端进程树耐久、实际WPF首尾渲染、受限外网下录音与导出故障隔离，以及两小时原件的完整混音/五分片复验见docs/44；这些既有实录为受控测试音源且mic关闭。Zoom/Webex客户端测试音只有有限证据。

双设备两小时公共声学同步没有可靠参考、干净Windows没有可用目标；真实会议、专用浏览器同时隔离对照、设备拔插与锁屏/睡眠仍未全验。单轨耐久和本机便携运行不代替这些项目。部分Windows N/精简系统可能缺少媒体功能；M4A不可用时明确报错并保留WAV，不静默安装或降低系统限制。

### 干净 Windows 验收步骤（尚未执行）

在获得授权的另一台 Windows x64 普通用户机器或已有合规虚拟机中进行，不为此更改本机系统功能或组织策略。记录准确 OS/build，确认未预装 SDK/.NET、没有模型，复制完整便携文件夹并核验 `release-manifest.json`。记录目录名使用匿名代号。

1. 断开录音器的网络访问或在离线状态启动，确认没有运行时/模型下载，界面与来源预检可用。
2. 用户主动触发已核对范围的合成音试录，mic 保持关闭；核验保存后完整混音、首尾测试标记、无关来源排除和暂停静音。
3. 保存后回放混音 WAV/M4A，导出大小受限的独立分段，逐份解码到 EOF、复核实际字节/重叠/尾段/清单；确认原轨哈希不变。
4. 用户另行明确同意后才启 mic，核验 mic 默认关闭、开关边界和真实讲话；不要把合成或无采集启动代替真实采集验收。
5. 记录通过/失败/未运行项、日志路径与残余进程检查；失败保留原件和证据。完成前 T46 一直为 NOT_RUN。

## 文件及依赖

- `ProjectEcho.exe`：主程序；`CaptureHost/`：单一采集进程及独立自包含运行时。
- `portable.json`：便携模式标记；`tests/audio_probe.html`：用户主动使用的本地合成测试页面。
- `THIRD_PARTY.json`：组件版本、官方包来源、源代码版本、包哈希和许可路径。
- `LICENSES/`：NAudio、.NET、Windows Desktop、System.Numerics.Tensors 许可与第三方通知。
- `release-manifest.json`：除清单自身外的全部随包文件、实际字节和 SHA-256；相邻 `.manifest.sha256` 文件给出该清单哈希。

包不包含 SDK、源代码、开发缓存、模型、真实录音或浏览器资料。ProjectEcho 仓库尚未由所有者声明公开再分发许可，本包的第三方许可清单不代表授予 ProjectEcho 本身的公开许可。当前二进制未签名；遇到 SmartScreen 或组织限制，应遵循批准流程，不关闭防护。

## 故障时

保留整个数据目录和原轨，不用派生文件覆盖它们。编码失败只影响导出；磁盘不足时先选择有空间的目录。来源丢失或 mic 设备失效时，重新明确选择并预检，不会自动改成其他麦克风或整个系统音频。崩溃恢复仅生成恢复副本，原件不改。
