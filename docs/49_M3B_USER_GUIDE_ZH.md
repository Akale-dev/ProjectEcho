# ProjectEcho M3b 中文界面使用说明

适用于 M3b 及本轮修复版界面。ProjectEcho 用来在本机录下电脑中播放的会议声音、保存独立原件、生成完整混音，以及在会后导入文字或运行本地语音识别。录音、导出和文字检索不需要连接在线服务。本文是操作说明；本轮测试结果与仍待验证的设备、平台范围以 [STATUS](../STATUS.md) 为准。

## 一、先认识界面

| 入口 | 用途 |
|---|---|
| **01 新会议录音** | 进入录音页，选择声音来源、决定是否开启麦克风、预检、试录和正式录音。底部录音操作栏只在这一页显示。 |
| **02 会议库** | 在左侧展开历史会议列表，按日期与名称寻找会议；点击一场后，在右边处理这场会议。 |
| **03 导入录音** | 把现有 WAV、MP3 或 M4A 音频复制进本地会议库。 |
| **04 诊断与设置** | 固定在左下方；查看状态、选择本地数据目录，以及切换明暗主题。 |

选择一场会议后，右边有四个标签页：

| 标签页 | 可以做什么 |
|---|---|
| **会议基本信息** | 查看当前会议、整理标题与项目，检查原件，必要时创建恢复副本。 |
| **导出音频** | 生成或重试完整混音，导出 WAV、MP3、M4A，设置分片大小、时长与重叠。 |
| **回听** | 播放已保存的录音、查看字幕、点击字幕定位；播放器在该页下方。 |
| **转写与搜索** | 导入已有文字或字幕、运行可选的本地识别、查找关键词、校订并保存新版本、导出字幕。 |

切换页面只改变正在查看的内容。正在录音时切换到会议库或设置，不会自动停止录音；要暂停、关闭本场麦克风或结束录音，请回到 **01 新会议录音**。界面显示的本场录制范围与麦克风状态是核对依据。录音、暂停及保存收尾期间，本程序所有回听均不可用。

## 二、第一次运行与保存位置

1. 把完整便携文件夹放在普通用户可写的本地磁盘中，双击 `ProjectEcho.exe`。保留旁边的文件和 `CaptureHost` 文件夹，不能只复制一个 exe。
2. 打开 **04 诊断与设置**，核对数据目录与磁盘空间。便携版默认使用程序文件夹中的 `Data`；开发版默认使用工程的 `.local`。
3. 如需其他位置，点击 **选择数据目录**。此操作只改变本次运行中后续数据写入和当前会议库的读取位置，不会搬走或删除旧目录中的会议。选择目前不跨重启保存；重启后回到默认目录，需要再次选回自定位置才能读取那里的会议。
4. 正常录音、回听、导出和文字导入不要求安装 SDK、.NET、Python、Node、FFmpeg 或识别模型。本地识别另需已经准备好的可信 CLI 与模型；便携程序不会自动下载它们。

本版只接受本地数据目录，不把录音写入网络共享目录。关闭程序前等待录音保存或任务收尾，备份时复制整场会议目录；只备份一段 WAV 会丢失用于重建时间轴的索引与其他来源。

## 三、场景：录制一场 Zoom / Webex 会议

### 录音前

1. 由你打开会议软件或会议网页，让会议声音通过这台电脑播放。手机电话拨入、独立会议设备等没有通过这台电脑播放的声音不在录制范围内。
2. 点击 **01 新会议录音**。标题可以使用默认日期时间，项目默认“未分类”，会后再整理即可。
3. 点击 **刷新来源**，在“实际音频会话 / 候选进程树”中明确选择本场来源。会议主窗口不一定是发声进程，应以实际音频会话为依据。
4. 通常选择“会议进程树”模式。其范围包含选定应用及子进程的输出；浏览器范围可能包含同一进程树内所有有声标签页，不代表某一个标签页或某一位参会者。
5. 如确实需要“端点兼容”模式，选择输出设备并确认其范围。该模式会录入该输出设备上其他应用和通知的声音；应用捕获失败不会自动切换到它。
6. 决定是否录自己的麦克风。默认关闭，只选设备不会开始采集。需要时，选定设备并勾选本场开启，阅读并确认麦克风提示。
7. 点击 **预检**，核对范围、设备和保存状态。预检不采集音频。首次使用或来源变化后，可主动点击 **10 秒试录**，先检查可控的测试声音。

网页会议可以通过“专用浏览器与试录提示”中的 **打开专用 Chrome 合成音页** 建立独立资料目录的 Chrome 实例，再由你在该实例中打开所需会议。启动后仍应刷新、选择实际音频来源并验证范围。普通新窗口、无痕窗口或浏览器名称相同，都不能证明音频隔离。

### 录音中与结束

点击 **开始录音** 后，观察远端 / 应用与独立麦克风的电平和健康状态。电平安静与设备失效是两种情况；如状态提示来源丢失或设备故障，应核对实际设备，不应把没有声音自动当成会议已经结束。

- **暂停 / 恢复录音**：暂停会停止采集；完整回放保留暂停经过的时间，以静音表示，字幕时间不会因暂停而整体前移。
- **开启 / 关闭 mic**：开始时未开麦、也未选设备，可以在录音中点击 **开启 mic**，选择设备并明确同意后开始采集。选择列表默认不选设备；成功开启后本场固定使用该设备。暂停时须先恢复录音再开启。显示“正在关闭”时，应等待采集线程确认边界；显示关闭后不再采集、保存新的麦克风 PCM。设备失效不会自动改用其他麦克风。
- **标记此刻**：保存一个时间书签，供后续查阅。它不剪切音频，也不自动生成任务或纪要。
- **停止并保存**：等待有效尾帧写入与原件收尾完成，再查看“已保存”或不完整警告。随后完整混音在后台生成，处理状态见会议的“导出音频”页。

Zoom / Webex 的静音按钮与 ProjectEcho 的麦克风开关互相独立。会议软件静音时，如果录音器麦克风仍开启，本地声音仍可能被记录。使用耳机可减少麦克风再次录入扬声器声音。

本版普通录音最长为 8 小时。混音、导出和识别都是会后任务，不会替代原件保存；它们失败时，保留原件并按提示重试。

## 四、场景：麦克风设为 44.1 kHz 或其他格式

麦克风的实际输入格式与用于回听、导出、识别的副本格式是不同层次的设置。不要因为混音为 48 kHz，就把系统麦克风必须设为 48 kHz 当成使用前提。

更换系统输入格式或设备后，回到录音页 **刷新来源 → 明确选择麦克风 → 预检 → 主动短试录**。程序按设备协商得到的实际格式保存原轨，再在会后构建统一时间轴的混音；识别时另生成 16 kHz 单声道副本。程序不修改系统默认格式，也不因格式差异自动更换麦克风。原轨不会因为识别需要而被改写为 16 kHz。

本轮已用 16、22.05、44.1、48、96 kHz 合成输入检查后续保存、混音和识别副本的时间轴；真实 44.1 kHz 麦克风采集仍未实测。具体设备是否接受当前格式，仍需以预检与主动试录为准。

如果预检或试录报告该设备格式不可用，应保留错误信息并检查本轮已验证的格式范围。44.1 kHz 的合成转换测试、真实设备短录和长时间双设备同步分别证明不同事情；具体已经完成哪一种检查，以 [STATUS](../STATUS.md) 和本轮验收记录为准，不能从“能生成 48 kHz 混音”推定所有设备组合均已通过。

## 五、场景：回听已保存会议

1. 点击 **02 会议库**，从左侧日期与名称列表中选择会议。
2. 可先在 **会议基本信息** 中修改标题、填写项目，然后点击 **保存归档信息**。这会保存归档资料，保留原始音轨与时间索引。
3. 打开 **回听**，使用下方播放器播放录音。重开会议会校验并复用已有混音，不会因点击列表重复生成。旧版混音如果缺少会议与时间索引指纹，或尚无完整回放，先在 **导出音频** 点击 **生成 / 重试完整混音**；本次生成后即可在以后安全复用，原件保持不变。
4. 用播放器的进度定位和图标按钮查找内容：三角形播放，双竖线暂停，方块停止；暂停后双竖线变为继续播放三角形。倍速下拉可选 **0.5x、0.75x、1x、1.25x、1.5x、2x**，字幕仍以原录音时间显示。
5. 选择有时间信息的字幕版本后，可直接点击 **导出字幕…**，以 SRT / VTT 保存当前回听版本的完整字幕。该版本可以与转写校订页选择的版本不同。

点击 **01 新会议录音** 会取消此前的会议库选择并清空旧会议的回听、字幕上下文；原件和后台任务保留。正在录音时，该按钮只返回录音控制页。

完整混音把远端声音与已同意录制的麦克风声音放在同一时间轴上，可直接听到同时发言。它保留暂停与已记录的缺口，不把两条来源轨首尾拼接，也不删除安静时段。原件不完整时，回听和导出仍可能提供覆盖整个已知时段的文件，但界面的警告仍然有效；不能把静音补位当成找回了缺失声音。

## 六、场景：导入已有录音

1. 点击 **03 导入录音**，选择本地 `.wav`、`.mp3` 或 `.m4a` 文件。
2. 等待复制原件、完整解码与回放校验结束。源文件不修改；成功后本地会议库中出现新会议。
3. 在 **会议基本信息** 中填写便于识别的标题与项目，然后回听、导出或转写。

支持的 WAV 为 PCM16、PCM24、PCM32 或 Float32 音频；压缩文件由 Windows 的媒体组件解码。单个输入最多 **32 GiB、12 小时**。取消或失败的导入不会显示成已完成会议。

导入录音的派生回放为完整的 **48 kHz 单声道 PCM16 WAV**，多声道平均合并；源文件副本仍保留原格式。回放和字幕以完整文件的 0 秒为起点。导入日期是加入会议库的日期，不证明实际会议发生时间；程序也不能由外部音频恢复原来的采集范围、设备时钟或缺口原因。

## 七、场景：在本机识别，得到文字与时间轴字幕

1. 在会议库选择一场已保存录音，确认完整混音已生成。
2. 打开 **转写与搜索 → 本地识别（可选）**。
3. 首次配置时选择可信的 `whisper-cli.exe` 和兼容的本地模型，核对来源和许可；如果有可信来源公布的模型 SHA-256，可以填写用于校验。
4. 选择语言：自动、中文或 English。点击 **保存本机配置**，然后点击 **开始 / 重试本地识别**。
5. 等待准备完整的 16 kHz 单声道 PCM16 识别副本，再等待本机识别进程结束。需要中止时点击 **取消文字任务**；之后可重试，每次尝试单独保存。
6. 识别成功后查看文字版本，检查漏字、同音字、专业名词与时间位置。可以进入 **回听** 对照音频，也可以在转写页选句校订。修复版按句末标点与可核对的模型 token 时间分句；不再固定每 48 字符切段。模型没有提供有效边界时保留原段，不按字数编造时间。时间仍是近似值，标点识别错误也可能影响分句。

已有转写不会自动改写。要使用新的分句逻辑，点击 **开始 / 重试本地识别** 生成新版本，再在回听页选择它；旧原稿和人工修订仍保留。

当前首选且实际可用的后端是 **whisper.cpp**。本机此前已配置的官方 CLI 与多语言 base 模型在 `H:\AI\Whisper`；如界面未显示该配置，或已换电脑 / 移动目录，须重新选择实际路径。配置保存在当前数据目录的 `settings/whisper.json`，不随音频导出。模型文件并非便携程序包的一部分。

本地识别会保存模型产生的 TXT、SRT、JSON，以及可供界面检索的规范化转写版本。SRT 是带起止时间的字幕；TXT 是便于阅读的纯文字。时间标记来自识别器，属于近似时间，仍需回听校对；识别成功不等于内容准确。完全数字零的输入不会送入模型生成文字，但其他安静、噪声片段仍可能出现误识别。

**Qwen3-ASR 只属于预留的后端扩展方向，本版不提供可运行的 Qwen3-ASR 选择项。**不能把 Qwen 模型路径填入 whisper.cpp 配置并期待兼容。未来接入应沿用会后副本、任务取消、原稿与修订分离的流程；当前录音、导出和已有文字不依赖这个后续实现。

本版是会后识别，不提供会议中的实时字幕，也不自动确认发言人的真实身份。

## 八、场景：导入文字、带字幕回听、搜索与校订

### 导入已有转写

在所选会议中打开 **转写与搜索 → 导入文字**，点击 **选择转写文件…**，填写来源名称，再点击 **导入到当前会议**。

| 输入文件 | 导入后的用途 |
|---|---|
| `.txt`、`.md` | 无时间文字，可读、检索和校订；不会猜测字幕时间，不能据此点击跳转或导出同步字幕。 |
| `.srt`、`.vtt` | 带起止时间的字幕，可按时间回听；时间必须有效，且不得超过当前会议时长。 |
| ProjectEcho `.json` | 符合 ProjectEcho 转写格式的结构化文字与时间；不是任意 JSON 文件。 |

单个转写或映射文件上限 **8 MiB**，使用 UTF-8 或带 BOM 的 UTF-16。Markdown、链接或字幕里的标签按文字处理，不会执行其中的内容。

如果文字来自音频导出分片，在“导入的是导出分片：设置时间映射”中选择该次 `export-manifest.json`，或本地混音目录 `export-records` 中的记录，并填写精确分片文件名，例如 `part-0001.mp3`。程序用所属完整混音的哈希核对映射，把分片时间换回会议时间。不要用另一场会议的映射，也不要先手动加偏移后再次套用映射。重叠分片的重复句子会保留供复核，不自动删句。

### 带字幕回听

在 **回听** 页选择一个带时间的转写版本。页面展示字幕，下方播放器显示音频位置。单击一句字幕，会跳到该句起点并播放；再次点击同一句可从头重听。键盘选中带时间的段落后也可按 Enter 回听。字幕时间以完整录音 0 秒为基准，包含录音时的暂停；它不以正在查看的分片或字幕行重新归零。

只有无时间 TXT / Markdown 时仍能正常播放录音，但不会生成伪造的同步字幕。压缩音频在不同解码器中的编码延迟解释可能不同；发现字幕偏移时，应先核对字幕是否对应当前完整音频，以及是否来自分片。

### 查找和修订

进入 **转写与搜索 → 字幕回放与校订** 时自动读取当前会议的版本，默认显示最新版本。返回同一会议的页面会保留已选版本和未保存的校订；需要重新从磁盘读取时点击 **读取转写版本**。输入关键词并点击 **搜索**。默认搜索所选会议；勾选“搜索当前数据目录的所有会议”可跨会议查找。搜索只读取本地文件。

选中一段修改文字，点击 **保存为新修订**。原稿和父版本保留，原有时间、来源与说话人字段不改。修订文字不会重新对齐音频；若字幕本身的时间错误，需要先在外部修正时间再重新导入新原稿。

选择识别原稿或修订版后，点击 **导出字幕 SRT / VTT…**，保存 UTF-8 字幕文件。导出保留完整录音时间轴上的毫秒起止，保留重叠与暂停；不会为了顺序播放把各段拼接或重排。请保存到会议原件目录之外。无时间文字不能导出为同步字幕。

## 九、场景：导出音频供保存或手动外部转写

1. 在会议库选择会议，打开 **导出音频**。必要时先点击 **生成 / 重试完整混音**。
2. 选择 **M4A、WAV 或 MP3**。WAV 适合无损保存与兼容检查；压缩格式通常更小。
3. 展开“分段与大小设置”，按实际需要设置每片最多字节、最多秒数及相邻片重叠。默认是 **20,000,000 字节 / 1,800 秒 / 5 秒重叠**，不是任何在线服务的上传承诺。
4. 如需携带分片与完整会议的时间对应关系，勾选 **另附分段时间映射清单**。
5. 点击 **导出供转写**，完成后点击 **打开导出目录**，检查生成的文件。输出放在当前数据目录的 `Exports` 中。

导出的是所选混音的副本或分片，不附原始麦克风轨、浏览器资料、会议链接、转写原稿或诊断日志。只有明确勾选时，导出目录才附带分片映射清单；不勾选时，本地仍保留映射记录用于以后导入文字。

导出只写本地文件。需要外部转写时，由你确认接收服务要求、选择文件并手动上传，ProjectEcho 不上传，也不保存 API 密钥。外部返回的文字或字幕可按上一节重新导入。

非常大的完整 WAV 可能使用 RF64 容器；内置播放器会优先选择已校验的可播放副本。若缺少可用的完整 M4A，可先重试编码，或导出播放器能处理的 WAV 分片。编码失败不删除原件或完整 WAV。

## 十、本地会保存哪些文件

以下路径都相对于界面显示的**当前数据目录**。用界面进入文件夹比凭目录名称猜测更可靠。

| 位置 / 文件 | 内容与用途 |
|---|---|
| `M1Recordings/<会议目录>/` | 普通录音与成功导入的外部录音；这是整场会议的备份单位。 |
| `meeting.json`、`filing.json` | 原始会议清单，以及录后保存的标题 / 项目归档资料。 |
| `sources/<来源>/…wav` | 本程序录制的独立原始 WAV 块；远端与开启过的麦克风分开保存。麦克风关闭期间不保存该来源的新 PCM。 |
| `sources/original.wav`、`.mp3` 或 `.m4a` | 外部导入录音的原格式副本，保留校验哈希。 |
| `journal/capture-index.jsonl`、`events.jsonl` | 本程序录音的包时间、格式、边界、检查点、书签与事件；用于重建时间轴和恢复。外部导入不伪造这些采集事实。 |
| `derived/<混音目录>/mixed_full.wav`、可用时的 `mixed_full.m4a`、`render.json` | 完整派生混音 / 回放副本，以及时长、哈希和警告等生成记录。 |
| `derived/<混音目录>/export-records/…json` | 本地分片导出记录，即使不随导出附清单也保留。 |
| `transcripts/original/<版本>/` | 导入或识别的原稿（原扩展名）和规范化 `revision.json`。 |
| `transcripts/reviewed/<版本>/revision.json` | 人工修订与父版本关系；保留原稿。 |
| `transcripts/asr-inputs/…/audio-16k.wav` | 会后本地识别使用的完整 16 kHz 副本。 |
| `transcripts/asr/<尝试>/` | 本地识别尝试的 TXT / SRT / JSON、运行输出、耗时和状态等记录；不等同于可公开分享的导出目录。 |
| `Exports/<导出目录>/` | WAV、MP3 或 M4A 分片，及按勾选附带的 `export-manifest.json`。 |
| `M0Recordings/` | 主动 10 秒试录及其检查资料，与普通会议库分开。 |
| `settings/whisper.json` | 当前数据目录的本机 whisper.cpp 配置，包含程序 / 模型路径等。 |
| `BrowserProfiles/Meetings/Chrome/` | 主动打开专用浏览器后产生的独立资料；可能含登录状态，不属于音频导出内容。 |

手动导出的 `.srt` / `.vtt` 保存在你选择的目标位置。应用不会自动上传上述文件。向他人提供音频时使用 **导出音频**；备份或迁移自己的工作资料时，保留整场会议目录与需要的配置，并妥善保管识别原稿和日志。

## 十一、遇到问题时

| 现象 | 先做什么 |
|---|---|
| 找不到来源、没有录到会议声 | 确认声音确实由本机播放，刷新并重新选择实际音频会话，预检后主动短试录；不要未确认就改成全部系统音频。 |
| 麦克风不可用 | 检查原先选定的设备和系统权限，重新明确选择；不会自动替换为其他设备。 |
| 历史会议不见了 | 在设置中核对数据目录，回到原来使用的位置再读取会议列表；切换目录不会自动搬迁会议。 |
| 不能回听 | 确认没有处于录音、暂停或保存收尾状态，并已生成 / 校验完整混音。 |
| 不能点击文字定位 | 检查是否导入了无时间 TXT / MD，或尚未选择带时间的转写版本。 |
| 本地识别不可用 | 核对 CLI、模型路径、来源 / 许可确认及完整混音；没有模型仍可录音和导入已有文字。 |
| 混音、压缩或识别失败 | 查看相应页的错误并重试，保留原件；原件保存与这些会后任务相互独立。 |
| 意外退出后录音不完整 | 在会议基本信息中检查所选录音，必要时创建恢复副本。恢复只包含已确认数据，不覆盖原件，也不保证找回尚未写盘的尾部。 |

本版仍有需要真实设备与现场环境验证的项目，包括双设备长时间同步、部分平台 / 浏览器隔离和干净 Windows 环境。识别的中文、中英混合、噪声和长会议质量也应以实际样本核对。详细结果与证据见 [STATUS](../STATUS.md)，便携依赖与历史限制见 [便携版说明](38_PORTABLE_GUIDE.md)。
