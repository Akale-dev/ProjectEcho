# 01｜产品需求

## 用户任务
用户经常通过 Zoom/Webex 讨论 project。录完得到完整可回听、可手动上传的音频；可选本地或手动外部转写；会后按需要归档到项目，后续查询决策、任务和未决问题。

## v0.1（M0–M2）必须包含
- 快速开始：默认“未分类”与日期时间会议名，项目/标题可录后修改；每场清楚显示并确认实际音源、录制范围与 mic 状态。mic 默认关闭，独立于会议平台静音。保存来源偏好不等于复用旧 PID，也不能静默更换麦克风。
- 用户主动开始、暂停、继续、停止；双路电平/权限检查；可选 10 秒试录；一个“标记此刻”书签。首次使用/来源变化突出试录提醒，不要求每场填写资料或重复向导。
- 持续分块保存、中断恢复、完整尾帧、真实时间戳/帧数；健康状态分别显示捕获连接、最近保存和电平，不能用安静直接判失败或用计时器证明有音频。按实际原始格式预算磁盘，并给导出/临时文件留空间。
- 停止后自动生成完整真实混音；提供“播放完整录音”和“导出供转写”。录音期间（含暂停）禁用本程序回放。暂停在首版输出中保留时长并填静音，缺口原因仍可查。
- WAV + 至少一种已验证的默认压缩格式（MP3 或 M4A）；M4A 为默认候选，第二种压缩格式可选、不阻塞交付。按时长和实际字节上限分段，保留尾段、重叠、导出清单与时间映射；打开本地导出目录。无模型可使用全流程。
- 简单会议列表与录后归档，先由 meeting.json 建立内存索引；含 CaptureHost、运行时和所选编码器的便携文件夹，经无 SDK/.NET 预装 Windows 验证。

桌面平台两项、Chrome 网页两项均在首版验收矩阵中，不能只测 Zoom 就宣称 Webex 已支持。无法实测某一项时标记 Not tested，仍交付已完成功能。

## 后续，均不阻塞 M2
M3 本地 ASR、结果导入、文本回放、修订版本与检索；M4 来源可查的项目纪要。按2026-09-30用户决定不加入SQLite，保留本地文件与按需内存搜索。可选精确浏览器标签页录音和本地说话人分段，没有承诺实名识别。

范围剪辑、删除暂停、自动寻找静音切点、音量/响度编辑界面、来源诊断 stereo 的普通入口、术语管理、书签分类和敏感区间编辑均延后。需要敏感区间处理时优先做保留时长的静音副本；不改原音。首版仍必须限制导出文件范围、允许预览，不能把原轨、浏览器 profile 或其他会议混进上传副本。

## 界面用词
“会议音源”“本地麦克风”“合并回听”“导出供转写”“仅这个应用进程树”“整个输出设备”“浏览器实例，不是单标签页”。
禁止“每位参会者单独一轨”“跟随 Zoom 静音”或“已经云端转写”这类未实现/不成立的标签。

## 关键用户故事
- 只录对方：不采集麦克风，远端轨和合并文件均完整。
- 我也发言：麦克风独立开启；平台静音时仍能清楚看到本程序状态。
- 我不装本地模型：会议结束仍有完整混音文件和按大小拆分的上传文件。
- 我马上要开会：无需先填项目/会议名，确认来源和 mic 后即可主动开始；录后再整理。
- 我用网页版：专用浏览器实例与日常 Chrome 分离，试录排除日常标签页声音。
- 程序崩溃：重开能找回已完成块，并清楚显示缺失/未完成部分。
- 转写听错：改稿不覆盖原稿，可回放原音证据。

## 边界
录音工具不替代会议参与者同意和组织授权。它不会自动产生平台原生录音通知，不依赖平台通知来证明已告知。真实声音只录当前电脑实际接收/产生的内容，不复原网络丢失的数据。
