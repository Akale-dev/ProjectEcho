## 对“支持”的准确约定
采用 Windows 输出音频捕获，不是平台内部 SDK，也不访问平台账号、会议后台、聊天记录或参会者名册。前提是会议声音实际通过当前电脑播放。手机拨入、独立电话音频、远端专用会议设备不经过该电脑的声音不在范围内。
Zoom/Webex 的 UI/主窗口 PID 不一定就是音频源。必须枚举实际音频会话和候选进程树，界面显示实际来源与范围；提供用户主动触发的试录，首次使用/来源变化时突出提醒，不要求每场完成试录向导。[S01,S02]
浏览器优先 Chrome；Edge 次优先并独立验收。不是所有同品牌浏览器会话都自动兼容。不能保证从整个浏览器进程树提取单一标签页。[S03,S04,S05]

## 非功能约束
运行版便携文件夹、普通用户权限、无虚拟驱动；开发先利用已有 Windows/.NET 工具。每台目标机检测实际 OS/build，不能从显示名或规划假设推定能力；本机历史检查见 `../STATUS.md`。低于 process-loopback 所需能力的电脑只提供明确标识、经用户确认范围的端点混录等降级，并分别检查 .NET/操作系统受支持状态。[S01,S08,S09]

## 核心取舍
- 默认未分类、按日期时间命名；录后可归档。每场明确展示/确认来源和 mic 状态，mic 默认关闭；一个“标记此刻”书签即可。
- 首个可用版包含完整混音、WAV 与至少一种已验证的默认压缩格式（MP3 或 M4A）、按大小/时长分段和便携包，不包含必须可用的 AI。M4A 是默认候选，第二种压缩格式可选、不阻塞 M2。
- 原始来源轨永久独立于派生合并音频；禁止自动覆盖或删除。
- 首版保持完整会话时间轴，暂停填静音；保留缺口原因及分片映射。范围剪辑、删除暂停、自动寻找静音切点、音量编辑器、诊断 stereo 普通入口、敏感区间编辑和术语管理延后；导出只含明确所选派生文件的保护仍是必需。
- 保留一个 CaptureHost、分块/journal 和失联停采；会议与转写检索使用可重建SQLite索引，原始文件继续权威；2026-10-01用户决定覆盖先前禁用SQLite。导出用简单可取消后台任务，不预建通用调度/插件框架。
- 录音期间（含暂停）禁用本程序所有回放；正常 Stop 保存有效截止边界前的尾帧，完成写盘后才显示已保存。实际时间戳/帧数和两小时同步验收不能因精简而删去。
- 独立会议浏览器实例是首版默认；精确 tabCapture 是可选后续，不是基础录音的安装前提。
- 外部上传由用户手动执行；不接收密钥、不内置自动上传、不假定任意聊天产品接受音频附件。
- 只做会后转写，不做实时字幕/视频/机器人参会。
