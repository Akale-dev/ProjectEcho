# 81｜M5C：已知人数的全场聚类修复

2026-10-04。M5C是M5B的聚类修复增量，不进入M6。用户已经正确使用TitaNet-Large、人数2、CPU6；本次没有将失败归因于设置错误，也没有再次只换模型。

## 查明的原因

先核验了实际程序/模型SHA、原始WAV、完整混音和16k输入。新例42.9909072秒，原轨双声道相同、无左右抵消或削波；raw→mix相关性0.9999999877；与前例重叠音频对齐后相关性0.999959，无声音特征被录制链抹除的证据。模型合并已发生在原生输出，界面没有串换人物ID。

利用相同原生DLL导出34个窗口的局部声音活动，并提取同样的72个TitaNet向量，可以将原程序14个错误区间逐个复现到毫秒。诊断中，向量实际上分出了两组主要人声，以及另一组短回应/非词发声；后者不代表第三个人。原complete-link方法按簇间最远距离合并，在最终强制两簇时把两组主要人声合并，把这组声学差异较大的短声音单列。指定人数2只限制结果数量，不能保证每组恰好对应一位真人。

保持音频、模型、窗口、全部有限特征向量和时间重建不变，只将**已知人数**聚类改成全场球面K-means后，主要人声恢复正确交替。16个固定初始化、最多80次迭代，以未加权声音余弦目标选优，不用字幕、人工A/B答案、性别或窗口时间位置选答案。不是每次换人递增编号，不删除短音频，也不建立跨会议身份库。

更换linkage、删短embedding、截短/补零等曾被验证为不能可靠修复，未作为产品方案。原始失败和诊断保留于`.local/M5C/native-diagnosis/`、`case-audit/`、`length-sensitivity/`；向量仅用于本地单场诊断，不放入包、Git或可分享日志。

## 产品实现

新增Windows原生worker，保留同名程序入口以兼容已保存的包内相对路径。原分段模型与TitaNet权重不变；依赖为固定sherpa C API与ONNX Runtime DLL，正常使用不需要Python、Node、SDK、管理员或全局环境修改。旧程序原件保存在新包Legacy目录供溯源，旧发布包完全不改。

- **已知人数：**新版全场球面聚类。算法与实际程序hash记录于analysis/attempt，不将旧分析重标为新版。
- **人数留空：**明确调用原C API自动人数/complete-link，原质量限制保留；没有把已知人数的改善套给自动模式。
- 程序、三项原生依赖、模型、输入与帧数均核对；缺少或改变原生依赖，在启动进程之前失败。
- 模型损坏、选错角色或缺文件在进入C API前由ORT验证，明确非零退出；进程内错误模式避免系统对话框卡住。只改变本进程，不改注册表或系统策略。
- 录音优先、取消只终止所属处理进程，原轨/混音/旧稿/人工版本保留；不上传任何数据。

源码在`src/ProjectEcho.Diarization.Native/`，构建脚本`Build-M5CSpeakerWorker.ps1`，依赖锁/源许可/源文件随包。原分段和投票时钟适配来自[sherpa锁定源码](https://github.com/k2-fsa/sherpa-onnx/blob/v1.13.8/sherpa-onnx/csrc/offline-speaker-diarization-pyannote-impl.h)；聚类替换是本项目代码，不伪称上游原程序。最终worker SHA-256：`70587ae81a60bcca819c5c5409e723ea20a061b7f5057e88e6774c3279f7677d`。

## 必要人工纠正

新增显式“手动输入换人时刻（本录音时间）”选项：先在人物正文里按实际发言补正文字，再将光标放到分界，填写`HH:mm:ss.fff`并选择左右人物。必须在本句起止之间、两侧文字非空；不会按字长产生时间。保存为新schema2修订，记录父hash、`split-segment-manual-time`和`human-entered-speaker-boundary`，与模型候选切点区分。

即使模型没有提供换人候选，也可以显式人工确认；旧候选API仍保持严格。切语言保留同段草稿与左右人物，换段/版本清空避免误用。旧人物版本独立保留；含新手填操作的稿需本修复版读取。

## 使用
