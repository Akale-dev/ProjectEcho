# 69｜M3Hfix：暂停同时停止录音与计时

2026-10-03—04。用户要求暂停时停止计时和两路录音，恢复后接续，并特别要求核对混音、时钟、帧抖动与转写时间轴。本决定覆盖旧版“暂停保留经过时间并填静音”的新录音行为；旧文件不重写。

## 行为与边界

- 点击暂停仍先显示等待确认；只有采集线程停止远端和mic后、释放完成才确认暂停。时钟固定在两路实际Stop截止边界，不把慢Dispose/尾部保存耗时算成录音。
- 已确认暂停时，计时、电平和音频帧不再增长；不会通过预录音预览另开mic。暂停中的书签、关麦、重复暂停不增加录音时长。
- 恢复先准备两路原生客户端和磁盘文件，这段等待仍不计时。第一个Start成功后从统一的恢复边界继续累计，保持两路同步。恢复失败或初始化中停止不启动迟到来源；部分来源已实际启动时保留其有效前缀，不倒退或抹除音频。
- 在暂停中停止，会保存到暂停时的有效录音长度。8小时上限按有效录音时间计算，暂停不耗尽它。录音、暂停和收尾期间仍禁本程序回放。
- 例：录10秒→暂停30秒→录5秒，计时和新混音为15秒，不插入30秒静音。真实设备缺包/系统故障仍单独报告，不把所有无声区间一律删除。

## 同一个录音时间轴

新会话/manifest使用`timelinePolicy=pause-excluded-v1`，每段持久化累计`excludedPause100ns`。原始QPC、设备帧位置、raw帧数、PCM保持独立和可审计；恢复、混音、导出及字幕使用同一有效录音时间轴。

恢复时的段偏移在客户端/磁盘准备后确定，并排在所有PCM写入之前；段的首个原始锚点仍来自真实包，不造时间戳。已准备但尚未开始的空段不允许扩张暂停时间。checkpoint保存有效录音观察时间，`LastCheckpointSessionUs`来自实际持久checkpoint，不用writer收到消息的时间代替。

WASAPI首包可能跨恢复边界。仅保留起点不早于恢复的完整帧，使用`RetainedFrameOffset`记录被排除的前缀；保留原始QPC/device/rawFrames。原始映射可以在录音0之前，但保留PCM起点必须非负。后续设备抖动处理锁定首个保留帧的位置，只调整余下连续区间，避免将它拉回上一段造成重叠或混音失败。停止仍保留真实截止前的排队尾帧。

旧文件缺少policy时按`elapsed-v1`读取，继续保留其原暂停静音；已有混音、字幕和原件不自动裁剪或覆盖。新render/export标注`pause_excluded_qpc_packet_mapping`，回放缓存核对实际policy及来源hash。SRT/VTT仍保留毫秒，书签与字幕不再把暂停偏移重复加回。
