## 实现

1. 共用Button模板原来把ContentPresenter写死为Center，使SidebarButton的Left设置无效。模板改为读取HorizontalContentAlignment，普通按钮仍默认居中，01–04和语言按钮实际左对齐；语言按钮固定为`EN/中`，三语言菜单和当前选项保持。
2. 回听继续按真实MediaPlayer时钟和字幕边界计算当前句，同步列表选中与ScrollIntoView；只在当前句变化、显式定位或重返回听页时滚动。自动选中不会调用Seek；暂停不会每帧抢回滚动，空隙清选。重叠字幕选最近开始的一句，上方仍显示全部活动文字；切版本跟随同一播放位置。
3. 本地识别明确分为准备音频、校验文件、加载模型、识别和保存。没有真实百分比或引擎仅报0%时显示不确定进度；收到正百分比后保留该真实数值，并显示独立活动提示和真实经过时间。计时器不推算百分比。结束/异常/取消释放计时器，旧任务晚到回调不改新任务界面。

## 为什么large-v3会突然跳到63%

已核本机whisper.cpp **1.9.4 / b5130**。`-pp`启用进度输出，`-p`是处理器并行参数。该版本CLI只在达到固定步长时打印引擎进度；底层回调在音频seek窗口边界触发。模型加载、首窗编码/解码及自动语言检测不能提供窗口内的真实百分比。因此大模型可能长时间没有数值，然后一次跳过很多百分比，最后一个窗口结束后直接保存。

这部分不能通过UI计时器变成真实的匀速百分比。本次没有切碎输入音频、改变解码线程/上下文参数或插入假进度；数值仍可能跳跃，但加载阶段、活动和已用时可见。另修复流式日志解析：收到完整`%`立即回报，不必等换行/进程退出。标准b5130通常带换行，不能把该防御性修复说成已证明的63%现象根因。

依据：[b5130 CLI](https://github.com/ggml-org/whisper.cpp/blob/b5130/examples/cli/cli.cpp)、[b5130引擎](https://github.com/ggml-org/whisper.cpp/blob/b5130/src/whisper.cpp)。公开样本及模型只从已存在的本地文件读取，没有下载或修改用户模型。
