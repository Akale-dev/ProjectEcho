# 04｜音频引擎与可靠性

## 原始录制
以 30 秒为默认文件边界，但 capture client 连续运行。原始来源轨保存实际协商的 PCM/float 格式、sample rate、channel layout、frame count；格式变化、停采后重启或时钟重置开启新 segment。原始轨不做降噪、VAD 剪掉静音或破坏性增益。支持整场一轨无声音、mic 从未启用、两轨起止不同。[T13,T16,T17]

Callback 只复制/归还系统 buffer、记录时间和投递受控队列，不做 ASR、数据库事务或压缩。池化内存在写盘与隐私截断完成前不得重用。积压达到上限必须告警并安全停止/明确记录丢失，不能无限扩容、静默 drop 或扩大范围。30 秒切块不能重复/漏样本。[S13]

先实现一个 CaptureHost 和可验证的时间映射，不预建通用 DSP/插件框架。保留时间证据，以合成时钟与目标电脑两小时试验决定漂移纠正复杂度；未达标则修正或明确限用，不能把缺乏测量当成无需纠正。[T23,T24]

## 共同时间轴
会话有 monotonic session epoch、wall-clock UTC+显示时区。保存每段设备时钟→会话时钟映射；不要用 DateTime.Now 作为对齐主时钟。
每个 packet 保存原始 device frame position、API QPC position (100ns)、原始帧数、flags、实际保留的帧区间、chunk 内位置、派生 session 时间和 timestampQuality。启停、设备替换重建 segment 映射；时钟突跳拆段/标记。完整落盘合同见 `11_STORAGE_SCHEMA.md`、`schemas/capture-index-record.schema.json`；退出后仅靠磁盘也必须可重建，不依赖内存中的映射。[T22,T53]
微软 API 的 SILENT、DATA_DISCONTINUITY、TIMESTAMP_ERROR 要处理；silent buffer 不能盲读空指针。[S13]
没有 callback 不等于没有时间流逝。分别显示连接状态、会话计时、最近有效包时间、最近写盘/checkpoint 时间；有效 SILENT、尚未观察到声音、无包和明确故障不是同一种健康状态。不能凭长时间安静自动停录或扩大范围。导出按时间轴填显式空缺/静音，不压缩时间。[T14,T54]

## Stop、Pause 与 MicOff 的生效边界
UI 发请求后显示“正在停止/暂停/关闭麦克风”。采集线程串行处理控制命令，回传 requestId、实际生效时间、segment 与截止帧位置；UI 发命令的时刻不是生效时刻。重复 Stop 使用同一结果，不重复 finalize。[T11,T15,T51,T52]

1. 采集线程关闭相应来源新数据入口，记录单调生效边界 B，停止/释放 client。Stop/Pause 作用于两路，MicOff 只作用于 mic；两路 B 可以不同，分别记录，不假称同时停采。停止 API 返回与末次回调收敛前不能回传“已关闭”。
2. 队列及停止时 API 剩余缓冲中的包仍按实际时间/帧位置判定。正常 Stop 保存所有可证实处于 B 前的完整帧，不能取消 writer 清空队列。Pause/MicOff 同样保留此前获准帧；B 后真实 PCM 不得进入存储队列、临时或诊断文件，已有队列也执行此边界检查。
3. 跨界包只保留完整处于获准区间的前缀帧；一帧跨 B 时舍弃该帧并记录最多一帧的边界舍弃，不存半帧。索引保留原包时间/帧数和实际保留偏移/长度，不能把截断后长度冒充原 API 包长。
4. TIMESTAMP_ERROR 等导致无法可靠判定跨界时，隐私优先丢弃有歧义包并标明缺口；不能当真实静音。正常 Stop 尾帧闸门因此不通过，显示 degraded；禁止为了简单连正常时间戳尾包也丢弃。
5. 释放 client、丢弃并清理应用持有的 B 后 PCM 后，回执才允许显示“已暂停/mic 已关”；此前合法帧仍可写盘。Stop 只有截止前队列全部写完、PCM/index 刷新、WAV 收尾校验、chunk finalize 和 manifest 更新成功后才能显示 Saved。任一步失败均明确保存不完整，保留可恢复原件。

mic 默认关闭时不创建/启动 mic client；off 期间不持续采集再把音量设为 0。恢复/重新开启创建新 segment、重新锚定；开启 mic 仍需明确用户操作，缺失设备不得自动替换。此前已获准录下的内容不删除。[T11,T15,T18]

默认合并文件保留真实经过时间：pause/gap 填静音并注明原因。删除暂停、范围剪辑与 compact 时间轴后移，不作为 M2 闸门；后续若实现必须保存 piecewise 时间映射。
Zoom/Webex 静音状态与本程序完全独立。独立 mic 可能包含平台未发送的私下声音；首次启用要确认，录制时持续提示。

## 分块与故障恢复
源文件采用 `.partial` + `journal/capture-index.jsonl`。索引含 sequence/hash；先写 PCM 和索引，刷新后追加 checkpoint 并刷新 checkpoint，列出可恢复 chunk 完整帧/PCM 字节水位。只承认音频字节与有效索引都覆盖的完整帧。定期刷新建议 ≤2 秒，作为待验证目标。完整块更新 WAV header/关闭校验后同卷 rename；manifest 临时写+同卷替换。跨文件不是事务，恢复需识别中间状态；不信任半行 JSON、错序或坏 hash。[T20,T53]
意外退出后扫描/校验已完成文件；对 partial 只修复可确认的完整 PCM frames，写 recovered 状态，不修改/伪造原始来源。不要承诺断电零损失：OS/磁盘缓存、控制器可能影响 durable 数据。定期 flush+30秒封块是目标策略，不是保证。
大于 RIFF WAV 容量上限的最终无损输出必须使用 RF64/FLAC 或分段，并验证目标工具可读；源块本身避免超大单 WAV。[S10]

## 音频设备变更
麦克风消失：mic fault + 独立轨缺口；不改录内置 mic。端点模式的输出设备变更：先提示录制范围变更，再授权重绑。process loopback 不绑定特定物理端点，但仍测试实际耳机/蓝牙切换行为，不因为 API 特性就宣称所有应用切换无缝。[S01]
推荐耳机，不默认 mic monitoring，不保证独立 mic 继承平台 AEC/降噪。M1 起录音（含暂停待恢复）期间禁用本程序旧录音/试录回放；开始前停止已有回放并确认播放器已停止，避免回录。外部播放器仍属所选范围风险，应明确提示。扬声器回灌会双录，不以简单互相关/删重复文本代替可靠回声处理。锁屏与睡眠/恢复实际行为须验证；缺口明示，不修改全局电源设置。[T49,T55]

## 原始轨磁盘预算
预检按实际格式计算 `sampleRate × channels × bytesPerSample × 秒数`，再为混音、索引和编码临时空间预留。两路 48kHz float32、远端双声道+mic 单声道约 2.0736 GB/小时（十进制，仅 PCM 算例）。不能用上传 MP3 体积预算原始录音；格式未知时先保守提示。[T21,T57]

## 目标阈值（待实测）
已完成块恢复率100%；合成时间轴对齐误差≤20ms；目标电脑2小时标记漂移≤100ms；无未报告缺口/额外来源；静音15分钟不缩短时长。正常 Stop 原件包含截止前最后一个完整有效帧，跨30秒边界/随机包位置/重复 Stop 均成立。混音与压缩导出以尾部短标记和 decode 检查证明最长尾段保留，不能只听“最后5秒大致有声”。均为待测验收线，不是当前成绩。[T13,T20,T23,T24,T26,T51]
