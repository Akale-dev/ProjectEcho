# 16｜关键决定与风险登记

| 决定 | 理由 | 重新评估条件 |
|---|---|---|
| Windows/WPF + .NET 10 | 符合本机/便携目标；不用游戏引擎 | 目标OS无法满足受支持运行条件 |
| NAudio候选 + 必要时窄原生互操作 | 复用音频基础而保留时间戳能力 | M0发现API生命周期/时钟信息不足 |
| Chrome独立实例先于扩展 | 不以安装扩展作为网页版录音前提 | 用户确需同浏览器其他页不被录且组织允许 |
| 分轨事实 + 派生真实混音 | 兼顾恢复、复处理和模型上传 | 永远不只保留混音后自动丢原轨 |
| 手动外部上传 | 用户明确只是“可能upload”，未授权自动外传 | 未来明确请求指定API与安全需求 |
| M2先可用、M3后AI | 本地识别失败不妨碍用更好外部服务 | 不改变 |
| 默认未分类+日期命名，单一书签 | 不让开会前整理资料阻塞录音 | 日常反馈证明需要额外必填项 |
| 每场来源/mic 可见并确认，试录主动可选 | 清楚范围与隐私，不重复强制向导 | 来源变化或实际故障时强化提醒 |
| 一个 CaptureHost + 简单后台导出 | 采集故障隔离有价值；通用平台无首版收益 | 实测瓶颈/可靠性要求确需增加组件 |
| meeting.json 与转写文件，按需内存搜索，不加入SQLite | 2026-09-30用户明确要求 | 只有用户明确改变该决定才重议 |
| WAV + 一种已验证压缩格式 | 避免 MP3/M4A 双格式拖延完整可用流程 | 同一编码器低成本支持第二种时可追加 |
| 完整时间轴、暂停填静音 | 减少编辑复杂度，保持分片和原音可追溯 | 后续明确需要编辑并补全 piecewise 映射 |
| 范围剪辑/敏感编辑/音量编辑/术语管理延后 | 首版优先完整录音与安全导出 | 核心验收通过后的实际需求 |
| 录音期间禁用本程序回放 | 最小成本避免反馈回录 | 有明确播放路由需求并完成隔离验证 |
| M2 即便携包与无 SDK 验证 | “可用”必须能在日常机器运行 | M6 仅扩大回归，不后移此闸门 |

## 风险与应对
进程选错/重启：session探测、PID+starttime、重新确认。
浏览器串音：独立user-data-dir+对照声音测试；scope提示；不是窗口选择器就能解决。
麦克风双录/私语：独立停采开关、耳机、off边界测试，不同步平台mute。
时钟漂移：保存实际时间戳/帧数/中断、验证可恢复最小映射、保留 2 小时验收（T24）；按证据增加纠正复杂度，简单开头对齐不够。
崩溃/磁盘：分块+journal+flush+可恢复partial，避免宣称零损失。
尾帧丢失：Stop/Pause/MicOff 生效边界可查，正常 Stop 排空有效队列后收尾；用合成末帧/短标记验证，不能只听最后五秒。
重启失去同步依据：segment/index/journal 落盘契约与恢复有效边界完整，退出后仅靠磁盘重建时间轴。
磁盘误预算：按原始协商格式而非 MP3 上传大小估算，并留导出临时空间。
睡眠/锁屏/回录：M2 前验证明确状态与缺口，不改全局电源设置；录音及暂停期间禁用本程序回放。
导出缺尾/超限：longest时间轴、decode probe、实际bytes与覆盖检查。
外部平台限制：可调导出大小/时长/重叠、由用户核实入口支持，不写死产品能力；首版不做服务商 profile 管理系统。
自包含分发：不代表零原生依赖；干净Win机器验收、license核验。

## 待M0解决，不提前捏造
目标机器 OS/工具链实况以 `../STATUS.md` 和本地环境证据为准，已有只读检查不能代表音频能力已通过。M0 仍待验证实际 NAudio 接口与时间戳、Zoom/Webex 渲染进程树、浏览器策略、mic 共享访问、用户耳机、目标性能和公司应用白名单。
开发过程能自行检测的不要重复问用户；涉及真实录音、资料外传、权限或组织限制不能擅自执行。
