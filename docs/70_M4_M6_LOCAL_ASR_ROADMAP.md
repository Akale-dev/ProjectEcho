## 2. 三阶段共同边界

- 全部会后、离线、用户主动触发；不进入 CaptureHost 或采集回调，不访问会议账号、参会者名单或麦克风。没有这些模型时，现有录音和导出继续可用。
- 不引入额外通用本地 LLM，不做 LLM 裁决、摘要或投资建议。ASR、VAD、声音特征和必要的音文对齐模型是各自功能组件，不等于不需要模型。
- 不上传音频、转写、提示词、声音特征或日志；不增加 API 密钥和云服务。导出继续由用户手动操作，不代表上传授权。
- 常规使用保持 Windows 便携和普通用户权限；不要求 Python、Node、WSL、Docker、管理员权限或全局环境修改。依赖、模型和许可须分别核实，不自动安装或录音时下载。
- 首版一次一个重型后处理任务，录音优先；使用实际可行的资源退让、延后或安全取消，不让下一场录音等模型完成。不能未经验证承诺原生进程支持暂停恢复。
- 保留原音频、原始模型输出、转写原稿及人工修订。失败或取消的尝试不能发布成完成版本；切会不改变任务归属，重跑不覆盖人工锁定结果。

## 3. 共用数据基础：在 M4 建最小合同，后两阶段扩展

不预建通用作业、插件或联系人框架。复用当前独立处理进程和可取消任务，补充实际需要的类型。

| 数据 | 必须保留的关系 | 使用规则 |
|---|---|---|
| 音频依据 | 会议 ID、源混音/识别副本哈希、版本、采样率及帧映射、timelinePolicy | 不能仅凭文件名、目录最新文件或近似时长绑定 |
| 模型尝试 | 后端/程序/模型版本与哈希、参数、实际硬件、输入、原始输出及完成状态 | 哈希用于本次运行溯源；不恢复已取消的“要求用户手填预期模型哈希”界面 |
| 转写与定位 | 不可变版本、父版本、原段和文字范围、句子起止、时间来源及质量 | 识别时间、后置对齐时间分别标注；未获得时间则明确无时间 |
| 说话人附层 | 分析版本、稳定 speakerId、显示代号/名称、区间及纠正记录 | 不把标签拼入原文；改名不改变人物引用 |
| 复核附层 | 输入转写版本、规则版本、音频范围、第二 ASR 原文、比较及人工状态 | 同一结果只适用于其引用的音频/文字；文字变化后重新核验受影响关系 |

权威资料保存在本地文件，SQLite 只作可重建索引。导出、重开、索引重建都必须读回同一版本关系；旧 transcript v2 保持可读，不凭空补说话人、置信度或复核结论。

新录音按 `pause-excluded-v1` 使用有效录音时间；旧文件缺 policy 时按 `elapsed-v1` 维持原有暂停静音。外部导入音频按其自身文件时间线处理，不根据静音猜测暂停。准备副本、分块、裁片、对齐、说话人和复核都映射回同一条音频时间线，局部偏移只应用一次，不重复加回暂停；原 QPC/device/frame 与分段偏移继续独立保留。

## 4. M4：中文 ASR、CPU/Vulkan 与句子级定位

目标是让 Qwen3-ASR 成为中文为主会议的优先选择，同时保留 Whisper。选择依据是目标机的真实质量与成本，不凭模型名称宣布优于现有引擎。固定候选运行路线为 [handy-computer/transcribe.cpp](https://github.com/handy-computer/transcribe.cpp)，模型来源参考 [Qwen3-ASR 官方仓库](https://github.com/QwenLM/Qwen3-ASR)。实际 commit、模型规格和分发文件在实施验证后锁定。

### M4-A：先验证 Windows 原生可行性

1. 读取现有工具与当前便携包，核对运行时、Qwen 模型格式、CPU 指令要求、Vulkan 后端、模型/程序许可和可分发依赖；不把 Whisper 的 Vulkan 成功证据套用到 Qwen。
2. 用公开或另获授权的标注样本验证 CPU 与实际 Vulkan 设备，核实输入格式、语言、原始输出、时码能力、取消、失败与进程退出。显式选择 Vulkan 后，CPU 回退不能算 Vulkan 成功。
   先比较 1.7B 质量优先与 0.6B 速度优先候选，量化方案在同一中文/混合样本上另验；不凭公开英文成绩或模型文件大小推定目标机质量、显存或速度。
3. 先解决句子定位可行性再完成后端适配，避免只完成全文识别后才发现无法满足用户的点击回听要求。若所选链路没有原生时码，就明确进入 M4-B 的最小补充路线。

### M4-B：句子定位与长音频处理

用户需要的是**每句点击后定位到对应发言**，不需要逐字高亮、逐字时间编辑或逐字字幕界面。内部可以使用字词边界取得句子起止，但不将内部粒度扩成新产品功能。

当前 Whisper 的分句依靠标点和可核对的 token 时间；缺少可靠边界时保留原段。Qwen 若只输出文本，不能只按标点拆句后分配时间，也不能把一个音频窗口内多句话全部挂在窗口起点，就宣布句子定位完成。

| 候选方式 | 能解决什么 | 不能据此声称什么 | 本阶段安排 |
|---|---|---|---|
| 现有/运行时音频窗口基线 | 限制单次输入、维持长会覆盖与全局偏移；作为质量和资源对照 | 窗口不天然等于句子，不能提供窗内每句位置 | 先核实实际实现，保留基线比较 |
| Silero VAD，原生 CPU 候选 | 检测语音活动、减少明显无声处理、辅助分块 | 一段连续语音可含多句，一句话也可跨停顿；VAD 不是音文对齐 | 只有实测改善且便携依赖合格才纳入；不作为无条件必装组件 |
| 最小音文对齐 | 对已识别文字寻找可信音频边界，再聚合成句子时码 | 对齐不证明转写文字正确，也不能把估计时间标成精确声学事实 | 无可靠原生时码时必须验证这条补充路径 |

Silero 资料入口：[官方仓库](https://github.com/snakers4/silero-vad)。它是否采用、使用哪个原生入口、版本与模型，仍为待验证决定。分块比较应检查接缝遗漏/重复、短插话、长句、静音幻觉及总耗时，而非仅以减少处理秒数判胜。

Qwen 官方提供的 ForcedAligner 可以列为对齐候选，但**目前不视为已由本项目所选 transcribe.cpp 支持**；官方 Python 使用路径也不满足本项目便携要求。M4-A/B 必须先证明能在目标 Windows 的原生依赖链中离线运行，再决定采用。若不成立，评估符合相同边界的最小原生对齐方案并记录选择；不能自动安装 Python 环境作为交付。对齐不预设必须支持 Vulkan，须分别报告 ASR 加速和对齐阶段的实际硬件、耗时、内存。

对齐输出必须严格对应所选音频与文字，保留来源和质量。失败区域标为“待定位”，不按字数均分、不覆盖用户校订、不拿旧 Whisper 的另一份文字时间直接贴到 Qwen 新文字。缺乏可靠逐句定位时，可保留识别小样，但 **M4 完整交付仍未通过**。

### M4-C：接入、比较与交付

1. 实现具体 `ILocalTranscriber` 适配，按实际能力声明语言、输入规格、时间来源和硬件；保留每场设置、独立版本、取消及重试。不能复制 Whisper 参数或把“接口预留”显示成支持。
2. 用同一批标注样本比较 Qwen 与现有 Whisper：自然中文、中英切换、数字/单位/否定词、金融术语、电话音质、噪声和无声。记录字符/词错误、关键事实错误及漏语音情况；合成语音只补边界测试，不替代自然会议质量。
3. 在 Windows 验证句子点击、完整字幕/尾句、重开/导出、中文路径、离线便携、取消和约三小时目标会议的资源/全覆盖。Qwen 是否作为中文首选，应随这些证据确定；引擎可用与质量更优分别陈述。

## 5. M5：同场换人、聚类、改名与局部拆句

以 [68 号](68_MEETING_SPEAKER_DIARIZATION_PLAN.md) 为主体，更新四点：改名是必交付；适配 Whisper/Qwen 的可验证时间来源；保持输入音频实际 timelinePolicy；原文中的后续“M4 文本模型”对应顺延后的分析阶段，与本功能无依赖。

### M5-A：验证声音归组

优先验证 sherpa-onnx 离线说话人路线及 Windows 原生/C# 接入，候选仍为分段模型、声音特征模型和全场聚类组合。先做 CPU 基线；具体模型、许可、阈值、未知人数估计与可选已知人数提示经样本验证后锁定，不继承任何 ASR 的 Vulkan 结论。

同一场必须全场一致：A-B-A-C-A 中再次返回的人保持同一组，分窗处理也须全场匹配，不能逐窗重置 A/B/C。先按首次可靠出现分配代号，再保存稳定内部 ID。短音、相似音色、回声和重叠缺乏证据时标待确认；不自动判断真实姓名，不将 remote/mic 当成“别人/自己”。

### M5-B：应用到选定字幕

使用引擎无关的音文映射。可靠换人在两句之间时直接标记；句内换人只在有可信文字边界时拆分。没有可靠映射时保留全部文字，标记多人/待确认并提供人工文字切点，不按字符比例分配。字幕内部模型时间和说话人边界均为估计，容差与拒绝规则需要实测。

M4 的 VAD、句子定位与 M5 的说话人分段职责不同。优先复用已保存的可信结果，不无条件增加另一套通用 VAD；说话人模型内部所需分段按其真实接口处理。导入 SRT/VTT 的句内换人可待确认；无时间 TXT/MD 不自动变成定时人物字幕。

### M5-C：纠错、改名与保存导出

必须同时提供：A/B/C 显示名称修改、单段改人、合并人物代号、将选定片段拆出新人物、必要的人工句内切点。改名只更新本场显示映射，不建立联系人或跨会议声音身份库；重跑保留旧聚类和人工修订，不静默重排已确认代号。

保存独立说话人分析及带说话人的转写版本。导出可选择是否包含标签，名称/代号作为输出前缀生成，不污染发言正文；SRT/VTT 的普通文本前缀不能被回导时自动当成可信身份。声音特征优先限于本次分析；确需缓存时随会议管理，不进可分享日志。

## 6. M6：可选深度复核

入口由用户选择“是否深度复核”；普通识别不自动承担第二遍模型成本。产品最终提供“重点片段复核”和“全文复核”。**开发验证先做全文第二遍对照，再加入选择性筛选**，以免筛选漏掉的问题从一开始就没有对照依据。

典型链路为：现有转写 → 用户选择复核 → 规则与音频覆盖检查 → 第二 ASR 重听音频 → 时间/文字对齐比较 → 保留一致结果、集中标记争议 → 带复核状态的独立转写版本。Qwen 主转写可用 Whisper 复核，反向亦可；优先不同 ASR 家族，不用同一模型重复运行冒充独立验证。

### M6-A／QA-1：规则标记与点击回听

先基于已有转写生成可定位标记，不接入第二 ASR、不自动改原文。

| 线索 | 示例与限制 |
|---|---|
| 低置信证据 | 仅使用引擎实际提供并有含义说明的分数；缺失就标缺失，不能伪造，也不能直接跨引擎比较阈值 |
| 金融关键表达 | 金额/币种、百分比/基点、单位量级、正负/否定、区间、日期与口径；只是复核触发线索，不生成事实结论 |
| 识别质量异常 | 异常重复、乱码、突兀长段、疑似漏句等；规则命中不等于原文必错 |
| 音频/文字覆盖异常 | 语音活动与字幕覆盖差异；VAD 自身也会错，不能仅凭差异断言漏音或补写文字 |

规则版本、命中原因和范围随复核结果保存。只建立转写中的标记与复核清单，**不另建金融候选报告**。

### M6-B／QA-2：先全文对照，再选择性重听

1. 先实现第二 ASR 全文识别与可追溯比较，验证两种分句方式、时间漂移、漏句、插入句、同义或格式差异及末尾内容。使用独立音频识别结果，不将第一稿当作要求第二模型照抄的答案。
2. 对比分为“复核一致”“存在争议”“证据不足/未完成”等状态。“一致”只表示两次结果在既定比较规则下相符，不是事实正确或人工确认。
3. 再实现选择性重听：规则候选合并、合理前后文、边界保护、局部时码映射及重复覆盖处理。裁片从已核验音频生成，不拼接不同来源冒充混音，不截丢尾句；短窗上下文不足时扩大范围或标不足。
4. 以全文对照和人工标注作参照，统计选择性筛选的漏报、复核覆盖与成本，检查“没有被选中”的区域，而非只评估已命中片段。数字门槛在发布判断前固定，不随结果调低。

默认复核已校验的完整混音；不能由 A/B/C 或显示姓名推定 remote/mic 轨。第二 ASR 不接收第一遍候选答案作为提示；若采用术语提示，应只含中性拼写信息。金融规则同时覆盖肯定的关键陈述，避免首遍漏掉否定词后筛选也漏检。比较必须保留数值顺序及关系，例如“从12%到13%”与“从13%到12%”、“下降了”与“下降至”不能判为等价。

选择性模式在未命中的语音区间安排分散抽查，比例通过样本验证确定；全文模式遍历全部音频窗口，不能仅重听首遍已有字幕或 VAD 命中的部分。记录实际处理范围与缺失范围，复核覆盖率不是准确率。重要争议最多扩大上下文再识别一次，仍有分歧就进入待确认，不循环重跑到碰巧一致。

文字比较可以单独忽略已定义的无语义格式差异，但原始文本保留；不得归一化掉数值、单位、币种、否定或口径差异。默认保留当前文字并保存候选与状态，不由模型多数票自动裁定争议。未执行的区间标未复核，超时、取消、无结果不记通过。

### M6-C／QA-3：争议阅读、人工锁定与带标记导出

在同一转写阅读流程中集中查看争议、播放对应音频、比较原文与第二 ASR 候选，允许人工选择、修订并锁定。人工确认、模型一致、仍有争议、未复核四类不能混为一个“已复核”勾选。人工锁定保存为新修订并绑定证据；后续重跑不得覆盖，相关文字/音频改变时提示重新核对。

导出明确所选版本及标记开关；带标记版本保留争议和未完成状态。无需逐条人工确认也可完成带标记输出，不让争议阻塞整场交付；转写完成、复核完成/部分未完成与仍有争议分别显示。纯文字导出不得暗示全文已核实。不做重点原文摘录、独立金融候选报告、摘要、跨段推理、投资建议或无人值守的事实裁决。
