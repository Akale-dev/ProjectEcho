# 51｜M3b 用户测试问题修复

2026-09-30。对应用户提出的七项问题。本次范围为已有 M3b 修复，不进入 M4。

## 用户反馈与本地错误记录

用户报告：Zoom 会议 **mic 关闭**时，录音、保存及转写已验收通过，记为 `PASS_USER_REPORTED`；此结论不扩大到 mic 开启或其他平台。

在旧 M3b 包的本地数据目录找到三次未完成录音：原始索引显示 remote 48 kHz、mic 16 kHz / mono / PCM16，麦克风每包 160 帧，设备帧连续，但 API QPC 包间隔发生约 0.76 ms 偏移。三次均未生成完整 `meeting.json`。只读取索引与技术元数据，没有识别、播放或上传会议音频。

旧版 writer 把超过一个采样帧的 QPC 重叠直接视为无效；16 kHz 一帧只有 62.5 µs。历史记录未保存被拒绝包和原异常堆栈，因此不能把故障原因称作逐包证实。回归使用三份记录已知的相对 QPC 序列，并**明确添加合成的返回正常节拍包**，复现旧判定失败，验证修复后的保存、边界与混音。合成补包不作为恢复到的真实音频。

## 七项修改

1. **麦克风时钟处理**：仅对设备帧严格连续、两包时钟有效且递增、当前包无断续标记的 mic，承认不超过 2 ms 且不超过前包时长 25% 的短时偏差。新增有符号 `clockJitter100ns`，保留原始 device / QPC / PCM。恢复必须从原值严格复算；远端 QPC-only 路径不采用这项规则。离线混音以完整原包为单位，按相邻实际 QPC 锚点映射，跨文件子片段共享映射。隐私截止、末包时长及真实缺口规则不变。这不是长期漂移或双设备同步已解决的声明。
2. **录音中首次开麦**：开始时不选设备也可点击开启，先选择设备并明确同意；成功回执后固定本场设备。打开失败不锁定未成功的选择，后续开关 / 暂停恢复不自动换设备。暂停时需先恢复再开启。新增 `recording-result.json` 保存录音收尾/失败技术信息，便于以后诊断。
3. **回听控制**：播放、暂停 / 继续、停止使用矢量图标，保留提示与无障碍名称。提供 0.5x / 0.75x / 1x / 1.25x / 1.5x / 2x；字幕位置保持媒体时间。
4. **回听导出字幕**：直接导出回听页选定版本的完整 SRT / VTT；不会误用转写页另选的版本。保留完整录音时间轴与原稿。
5. **句级字幕**：移除 `-ml 48` 固定长度切段，请求 whisper.cpp 完整 token JSON，按句末标点及能与原 SRT 核对的 token 边界拆分，有限合并相邻未完句。缺少、错乱或不匹配的 token 时间时保留原段，不按文本长度造时间。仍标 `approximate`；模型标点和语音时间判断仍影响质量。历史版本不改写，重跑识别生成新版本。
6. **自动读取版本**：进入“转写与搜索 → 字幕回放与校订”自动读取当前会议。重复进入保留已选版本和未保存文字；手动读取按钮继续可用。异步返回时核对当前会议，避免旧会议结果覆盖新会议。
7. **新会议清除选择**：点击“01 新会议录音”取消旧会议库选择，清除旧回听 / 字幕上下文。正在录音时只返回录音控制页。

## 失败及复审记录

- 回听新测试第一轮遇到新增自动读取与旧夹具竞态：旧夹具在自动读取仍忙时立即导入字幕，操作被合理忽略。已使夹具等待实际任务结束；保留首轮 FAIL，不降低生产互斥规则。
- 复审发现初稿离线映射只调整最后一个跨块子片段，会使 159+1 帧拆分处的负偏差变成重叠，正偏差集中在一个采样帧。改为原包统一映射，并增加跨 30 秒切块的正负偏差与恢复副本检查。
- 首个修复包真实 Whisper UI 识别已成功，但旧夹具硬编码 JFK 必须拆成三段，因新分句正确输出完整一句而 FAIL。夹具改为断言完整一句、识别关键短语、近似时间范围和新 token 分句参数，并重新发布验证；原 FAIL 与首个包保留。
- 首轮新增时钟测试把非整数截止位置向下取整，错误地要求仍在截止前的最后一个输出采样静音。按输出采样时刻严格小于截止的规则改为向上取整样本数量；原始 mic 的完整帧截止规则未变。保留 137 PASS / 2 FAIL 首轮证据，最终回归以本报告新结果为准。
